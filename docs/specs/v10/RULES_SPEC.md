## 2. 关卡周期

### 2.1 结构

24 关分为 8 个周期，每个周期 3 关。配置里每关新增字段 `stageKind`：

| 周期内 | `stageKind` | 规则 |
| --- | --- | --- |
| 第 1 关 | `normal` 普通关 | 目标、奖励与以前相同；没有高压选项 |
| 第 2 关 | `pressure` 高压关 | 开始前可选“普通挑战”或“高压挑战”。高压目标 = 普通目标 × 1.5，过关金币 5 → 10 |
| 第 3 关 | `boss` 首领关 | 带 1 个首领减益（第 3 节）；没有高压选项；过关金币仍为 5；通关后的商店里有首领战利品（第 4 节）。第 24 关是终局首领，通关即胜利，没有战利品 |

### 2.2 周期计划

新建挑战时一次性生成 8 个周期的计划（每周期：首领减益 `modifierId`、战利品种类 `lootKind`），存入存档。使用独立随机流（种子 ^ `rng.stageSeedXor`），因此同一种子的首领顺序固定，不受玩家操作影响。

- 减益：第 1–7 周期从常规减益里抽，条件是 `minCycle ≤ 周期号` 且本局尚未出现；权重 = 档位（一档 1、二档 2、三档 3）。第 8 周期从 9 个终局减益里等概率抽。
  一档 `minCycle` = 1，二档 = 2，三档 = 4。所以第一个首领只会遇到一档减益。
- 战利品：第 1–7 周期按 `lootKinds` 的权重抽，且不与上一周期相同。第 8 周期没有战利品。
- 抽取顺序：周期 1 的减益、周期 1 的战利品、周期 2 的减益……周期 8 的减益。

### 2.3 首领关的生效范围

首领减益从“开始挑战”起到该关结算完成为止生效。被替罪羊（C131）或破咒符（I08）解除后，本关按没有减益处理（`modifierNullified`）。

开始首领关时按下面的顺序处理（普通关与高压关只做 1、5、6、7）：

1. 祭坛（C100，沿用 v0.9）。
2. 替罪羊：减益尚未解除且持有真实的 C131 时，最左侧的一张自毁，减益解除。
3. 确定本关失效的控制器（减益 `DisableLeftmost` / `DisableRarity`，按第 1、2 步之后的顺序）。失效的控制器本关没有任何技能、附魔不触发，也不能被百变模仿复制出技能；它仍然占栏位、仍然计入控制欲与草根逆袭的件数。它的成长值在本关（含本关结算）不变：投掷、使用道具、提交后、玻璃骰碎裂、牌型提升、结算时的成长都不发生，昙花一现（C141）的计数也不走。“最左侧 n 件”按位置数，带不占栏位附魔的卡也算在内。
4. 减益的入关效果：`LoseHalfGold`。
5. 关卡开始类控制器，按从左到右：吹玻璃（C128）、雇佣兵（C136）、百宝袋（C110）。失效的不执行。
6. 冻结控制器顺序与模仿绑定（沿用）。
7. 计算提交栏容量、提交次数、每手投掷次数（含减益的增减与附魔沉默），开始第一手。

## 3. 首领减益

配置字段：`id`、`displayName`、`tier`（1–3 常规，4 终局）、`minCycle`、`effects`（效果代码数组）、`amount`、`filter`、`description`。

### 3.1 效果代码

计分类（写入提交快照的 `modifierId`，由计分器读取；减益已解除时快照里为空）：

| 代码 | 规则 |
| --- | --- |
| `SealOdd` / `SealEven` | 有效点数为奇数 / 偶数的提交骰被**封印** |
| `SealLow` / `SealHigh` | 有效点数 1–3 / 4–6 的提交骰被封印 |
| `SealRed` / `SealBlue` | 有效颜色为红 / 蓝的提交骰被封印 |
| `SealFirst` | 第一颗提交骰被封印 |
| `SealAlternate` | 提交栏第 1、3、5、7 位的提交骰被封印 |
| `NoStraight` | 顺子不成立（主牌型、顺子倍率与读取“顺子成立”的卡都按不成立处理）。简单顺子（C29）的触发条件就是“顺子按它的长度成立”，所以它在禁顺下不触发，它的附魔也不触发；顺水推舟（C83）、一条龙（C142）同理 |
| `SmallHandsOnly` | 同点牌型只在一对、两对、三条里成立；三条带一对、三对子、四条、双三条、豹子、四对子及以上都不成立（读取“提交含某牌型”的卡同样按不成立处理；读取同点数量的卡不受影响） |
| `NoRepeatHand` | 本次主牌型不是散点、且本关此前已有一次有效提交以它为主牌型时，牌型倍率固定 ×1 |
| `HandHalf` | 牌型倍率减半：`max(100, 牌型倍率100 ÷ 2)`，整数除法（单位 0.01） |
| `ZeroLevels` | 所有牌型与颜色按 0 级计算 |
| `NoRed` | 红组倍率固定 ×1；全红的颜色倍率固定 ×1 |
| `NoBlue` | 全蓝的颜色倍率固定 ×1 |
| `FirstHalf` | 本关第一次提交（`submissionOrdinalBefore` = 0）的得分 ×1/2 |
| `LaterHalf` | 本关第二次及以后的提交得分 ×1/2 |
| `PipsOnly` | 基础分只计“有效点数 × (1 + 再计次数)”之和与未用投掷奖励：逐骰加值、逐骰倍率（飘忽不定、始终如一、玻璃、黄金）、控制器的整手基础分加值、基础分附魔全部不计 |
| `GrowthZero` | 成长型控制器的成长值按 0 计算（乘法卡 ×1，加法卡 +0）。只影响计分取值，成长计划照常产生。成长型指带成长值的卡：C54–C62、C90、C100、C129、C132、C134；人员流动（C51）、收藏家（C63）、昙花一现（C141）不属于成长型 |
| `EnchantSilence` | 基础分附魔、倍率附魔不触发；提交增加、投掷增加附魔不给次数。不占栏位附魔不受影响 |

被封印的骰子：点数贡献为 0（逐骰加值、倍率、再计都不产生分数），但仍参与牌型、颜色、红组、数量与位置判定。留池骰不会被封印。
封印只改这一颗的点数贡献：它的再计次数照常记录（乘以 0）；排头兵（C108）读取第一颗的有效点数，不因封印减少；骰面变更（5.3）对被封印的骰子照常产生。
`NoRed` / `NoBlue` 只固定倍率：颜色牌型编号、红组数量，以及读取颜色或红组的卡（C02、C25、C69、C73、C146 等）的触发都不变。

会话类（由对局流程执行）：

| 代码 | 规则 |
| --- | --- |
| `RollsDelta` | 每手投掷次数 + `amount`（负数），最少 1 |
| `RollsFixed` | 每手基础投掷次数固定为 `amount`（附魔与再给一次不再增加）；道具“增加投掷”和再来三次仍然有效 |
| `SubmissionsDelta` | 本关提交次数 + `amount`（负数），最少 1 |
| `CapacityDelta` | 提交栏容量 + `amount`（负数），最少 1 |
| `TargetPercent` | 本关目标 × `amount` ÷ 100 |
| `MustFill` | 提交时已锁定的骰子数必须等于 min(提交栏容量, 当前存活骰子数) |
| `NoItems` | 本关不能使用道具（破咒符除外） |
| `LoseHalfGold` | 入关时失去一半金币（失去 ⌊金币 ÷ 2⌋） |
| `TaxPerDie` | 每次有效提交计分并结算收入后，每提交 1 颗骰子失去 `amount` 金币，扣到 0 为止 |
| `NoReward` | 本关结算没有过关金币与剩余提交奖励；利息与控制器收益照常 |
| `GrowthFreeze` | 本关内（含本关结算）所有控制器的成长值不变 |
| `HandDowngrade` | 每次有效提交后，本次主牌型（散点除外）等级 − `amount`，最低 0 级 |
| `DisableLeftmost` | 入关时最左侧 `amount` 件控制器本关失效 |
| `DisableRarity` | 入关时稀有度为 `filter` 的控制器本关失效 |

## 4. 首领战利品与商店赠礼

### 4.1 赠礼组

商店新增“赠礼组”：一组免费报价，最多拿 `picks` 件。组内报价与普通报价走同一套购买规则（栏位、道具槽、目标选择、合法性），只是价格为 0。
拿满 `picks` 件后，组内剩下的报价作废。赠礼组不受刷新影响，不占各分类的货架格数。控制器不会同名并存：战利品与赠礼的控制器候选不含货架上已有的控制器，刷新货架时也不会刷出赠礼组里已有的控制器；道具、骰面改造、牌型升级可以与货架里的同名商品并存。
每个赠礼组生成在商店其余内容之后（随机流顺序：原有内容 → 战利品 → 控制器赠礼，从左到右）。

赠礼组里拿骰面改造算作“在商店购买骰面改造”（千锤百炼成长）；拿牌型升级算作升级（学无止境按实际级数成长）。

### 4.2 战利品

通过第 3、6、…、21 关后的商店带一个战利品组，种类是周期计划里预先抽好的那一种：

| 编号 | 名称 | 权重 | 内容 | 可拿 |
| --- | --- | --- | --- | --- |
| L1 | 稀有控制器 | 30 | 3 张未持有的稀有控制器，无附魔 | 1 |
| L2 | 附魔控制器 | 20 | 3 张未持有的控制器（按常规稀有度权重），各带一个随机的非空附魔 | 1 |
| L3 | 牌型精研 | 20 | 3 个当前可研习的牌型或颜色，选中的直接 +2 级（不超过上限） | 1 |
| L4 | 骰面工坊 | 10 | 3 项有合法目标的骰面改造 | 3 |

### 5.2 计分顺序（完整，粗体为 v1.0 新增）

1. 有效点数与有效颜色：不要奇数、首当其冲、红色浪潮、**蓝色浪潮（全部视为蓝；与红色浪潮不能同时生效）**。
2. 牌型、顺子、主牌型、颜色牌型。**`SmallHandsOnly`、`NoStraight`、`ZeroLevels`、`NoRed`、`NoBlue` 在这里生效。**
3. 红组：沿用。**锦上添红（C146）触发时红组数量 +1**；场外红人照旧并入留池红骰。红组奖励按 min(数量, 8) 查表；`NoRed` 时固定 ×1。
4. 判定每个来源是否触发。**失效的控制器没有技能，不参与判定；它也不产生任何计分后计划（提交后成长、主动颜色轮换、随机倍率重抽）。**
5. 逐骰贡献：有效点数 → 各来源的逐骰加值 → 飘忽不定 ×3 → 始终如一 ×2 → 玻璃 → 黄金。**`PipsOnly` 时只取有效点数；被封印的骰子为 0。**
6. 点数合计 = Σ 贡献 × (1 + 再计次数)。
7. 基础分 = 点数合计 + 未用投掷奖励 + 整手加值（对穿肠、有钱真好、有也不交、稳稳分数、成长加法卡、板凳深度、厚积薄发、越挫越勇、天生一对、**排头兵、囤积居奇**）+ 基础分附魔。**`PipsOnly`、`GrowthZero`、`EnchantSilence` 在这里生效。**
8. 牌型倍率 = max(×1, 同点牌型倍率 + 顺子倍率 + 牌型倍率加值（成双成对、三足鼎立、**一条龙**））。**之后依次应用 `NoRepeatHand`、`HandHalf`。**
9. 得分 = 基础分 × 牌型倍率 × 颜色倍率 × 红组倍率 × 各控制器倍率（按控制器从左到右）× 倍率附魔 **× 灵光一闪（×2）× 首领减益系数（`FirstHalf` / `LaterHalf` 的 ×1/2）**，最后向下取整一次。
10. 计分后计划：沿用，**新增骰面变更列表（5.3）、一掷千金的扣款**。

### 5.3 骰面变更列表

计分器根据冻结快照生成 `faceChanges`，会话在原有的计分后效果（骰子复制、红色主义、不断成长 / 缩小射线、红色扩散、蓝色扩散）之后按列表顺序逐条执行。
列表按触发来源从左到右排列；百变模仿复制这类卡时同样产生一份。每条：来源、骰子、面、类型、数值。

| 类型 | 执行 |
| --- | --- |
| `pipDelta` | 该面永久点数 + 数值，夹在 1–6 |
| `pipSet` | 该面永久点数 = 数值 |
| `color` | 该面颜色 = 文本（red / blue） |
| `gold` | 该面黄金 = 数值（1 有、0 无） |
| `texture` | 该面纹理 = 文本 |
| `weightDelta` | 该面权重 + 数值，夹在 1–`maxFaceWeight` |

“朝上面的永久点数 / 颜色”一律取冻结的六面数据里那一面的永久值（不是遥控覆盖值，也不是有效值）。没有六面数据的合成快照不产生骰面变更。

### 5.4 骰面权重

每个骰面有权重（缺省 1）。投掷概率先按权重归一，再套用纹理、道具与概率类控制器的既有规则。灌铅（C124）与配重（U10）能提高权重，上限 5。

## 8. 连带规则

| 问题 | 规则 |
| --- | --- |
| 百变模仿与新卡 | 复制完整技能。成长值共用且不另外成长；被动数值类（C110、C111、C113、C133、C136、C140、C145）按来源数叠加，其中 C140、C145 多个来源效果相同；自毁（C131、C141）、关卡开始的改骰（C128）只由真实实例执行 |
| 失效与模仿 | 模仿自己失效时没有技能；模仿的目标失效时模仿没有技能 |
| 失效与预算 | 失效的再给一次、多交一手、双刃剑、增加提交、大量提交、简化提交不改变本关预算与容量；它们的附魔同样不生效 |
| 失效与经济 | 本关失效的经济卡在本关的提交收入与本关结算里不生效；到商店时恢复 |
| 首领减益与预览 | 关卡选择页显示的投掷 / 提交 / 容量与目标，按“祭坛生效后、减益生效中”计算；有替罪羊时按减益已解除显示 |
| `MustFill` 与没有骰子 | 存活骰子少于容量时按存活骰子数要求 |
| `HandDowngrade` 与牌型提升 | 先执行牌型提升，再降级；学无止境只按升的级数成长 |
| `GrowthFreeze` | 暂停的是入关之后成长值的一切变化：提交后成长、投掷成长、碎裂成长、使用道具成长、结算成长、昙花一现的衰减。祭坛在减益生效之前结算，不受影响；卖价加成、成长基金不受影响。它是会话类效果：计分器照常给出成长计划，由会话决定不执行 |
| `TaxPerDie` 的时点 | 计分、提交收入（存钱罐、以战养战）与一掷千金扣款之后 |
| 一掷千金与有钱真好 | 都读取冻结钱包；一掷千金的扣款不回算本手 |
| 高压锅 | 以高压挑战开始并通过的关，在结算时成长 |
| 赏金猎人 | 计入结算的“控制器收益”；`NoReward` 不影响它 |
| 滥竽充数 | 候选是全部未持有的普通控制器，等概率；新卡排在最右；没有候选或没有空位时不执行 |
| 回收大王 | 影响卖出、以旧换新的抵扣与界面显示的卖价；聚宝盆加成、基金累计照旧另加。在当前这家商店里取得的控制器（购买、领取战利品或赠礼、以旧换新换来的）在离开这家商店之前按半价回收，所以买进再卖出不会赚钱（含砍价高手），刚领的战利品也卖不出高于折现的价 |
| 以旧换新的净价 | 可以为负（旧卡回收价高于新卡买价时找零），沿用 v0.9 |
| 破咒符与成长 | 破咒符本身算一次道具使用：先解除减益，再结算物尽其用的成长（所以解除“停滞”的这一次也成长）。解除后，入关时没有执行的关卡开始类效果（吹玻璃、雇佣兵、百宝袋）不补执行 |
| 结算顺序 | 冻结结算金额 → 成长基金 → 结算成长（老当益壮、余勇可贾、屠龙者、高压锅、昙花一现计数）→ 昙花一现到期自毁 → 聚宝盆 → 拔苗助长 → 大事化小 → 随机生成类（从左到右）。昙花一现腾出的栏位可以被同一次结算的滥竽充数填上 |
| 首领目标与以战养战 | 厚墙、天堑改的是本关目标；以战养战的“本关目标的一半”按改过的目标算 |
| 防碎膜 | 持有任意来源时碎裂概率取 2%；本关失效时恢复 8% |
| 吹玻璃 | 每个真实实例各作用一颗；没有非玻璃永久骰时不执行。不算“购买骰面改造” |
| 雇佣兵 | 每个来源各加一颗，受上限约束；临时骰在关卡结算时消失（沿用） |
| 百宝袋 | 每个来源各给一个，背包满时不给 |
| 蓝色浪潮与首当其冲 | 浪潮最后生效，覆盖首当其冲 |
| 灵光一闪 | 本手没有提交就结束本关时，效果作废；道具已消耗 |
| 点金笔 | 只能在选择阶段使用；目标是提交栏第一位的骰子当前朝上的物理面 |
| 扩容符 | 可多次使用，每次 +1，到 8 为止；破咒符重算时保留 |
| 镜像（U11） | 只复制点数与颜色，不复制纹理、黄金与权重 |
| 配重与灌铅 | 共用上限 5 |
| 战利品与栏位 | 控制器战利品需要栏位；可以先卖出再领取；也可以折现 |
| 贿赂首领与终局 | 第 21、22、23 关后的商店可以重抽终局减益 |
| 赠礼组与刷新 | 刷新只换货架里的控制器报价 |
| 旧的 260 + 160 条黄金样例 | 新字段缺省时计分结果不变 |

`faceChanges` 各类型的取值：`pipDelta`（`amount` = ±n，`text` 空）、`pipSet`（`amount` = 点数）、`color`（`amount` = 0，`text` = red / blue）、`gold`（`amount` = 1 或 0）、`texture`（`amount` = 0，`text` = 纹理）、`weightDelta`（`amount` = +n）。
同一来源内的顺序：C118、C122、C123、C124 按提交顺序逐骰；C125 先第一颗后最后一颗；C126 按留池骰顺序；C127 依次为 `pipSet`、`color`、`texture`、`gold`。

失效控制器在计数里的处理：控制欲（C47）、草根逆袭（C152）仍把它们计入件数；留白（C151）仍把它们算作占用栏位（带不占栏位附魔的失效控制器照旧不占普通栏位）。
`growthChanges`：失效的 C54–C57 不列。
字段类型：`goldSpent` 与 `faceChanges[].amount` 是整数；`globalFactors` 的分子分母是字符串；`faceChanges[].text` 在该类型没有文本时为空串。
逐卡细则：表里同色（C118）每颗提交骰各出一条，对面已是该颜色也照出；移花接木（C127）的 `texture` 原样带来源纹理（含 `none`），来源不是黄金面时 `gold` 为 0；灌铅（C124）每颗提交骰固定列 `weightDelta` +1，上限由会话执行时夹取；锦上添红（C146）的 +1 计入红火（C57）成长条件读取的红组数量；逆流而上（C130）在首领关减益被解除后仍然触发（读取的是关卡类型）。
成长归零（`GrowthZero`）时成长型乘法卡的倍率为 ×1（仍算触发），成长加法卡的加值为 0（不列入 `controllerBaseAdds`）。
