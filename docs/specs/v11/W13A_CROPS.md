表格式为 `icon-crops-1`。与示例相比多一个顶层字段 `units`，用来写明单位。

- **键序**：键按普通字符串排序，即 `C10 < C100 < C11`。
- **小数位**：`x`、`y`、`size`、`confidence` 一律固定 4 位小数。
- **确定性**：两次运行逐字节相同。
- **`note` 字段**：可选，只在有扣分原因时写，或为覆写项写明理由。

**单位**：W×H 是源图像素尺寸。

- `x = left/W`，`y = top/H`（从上往下量），`size = 边长/min(W,H)`。
- 在 Unity 中（原点在左下）：`side = size*min(W,H)`，`Rect(x*W, H - y*H - side, side, side)`。

**非方形源图**：184 张中有 11 张不是 1254²。

- 1312×1199：C02、C07、C09、C17
- 1536×1024：C06、C12、C13、C15、C18、C19
- 1774×887：C08

这 11 项各自带 `imageSize` 字段。顶层的 `imageSize` 取最常见的尺寸，即 [1254, 1254]。

## 2 方法 `alpha-core-1`

所有长度都按源图短边 S 的比例计算，分析在短边 512 px 下进行，因此与分辨率无关。

1. **主体质量**：alpha ≥ 0.5 视为不透明。用半径 2.8%·S 的圆盘做开运算，得到主体的“厚核”。动作线、闪光、网点、虚线、绳和弧线都比这个圆盘细，开运算后几乎不留核。
2. **保留部件**：一个连通部件要被保留，需同时满足两条：
   - 它的核不小于最大部件核的 2%；
   - 它的外缘至少 30% 是深色墨线。这一条只在主体本身有墨线描边时启用；平涂的动作线没有墨线描边。

   被保留的部件连同它的细节整体保留。
3. **全主体方框**：取最小的正方形，要求包含 99.5% 的核和 97% 的轮廓。
4. **聚焦方框**：在全主体方框的基础上最多缩小到 78%，同时至少保留 88% 的核。缩小时只允许削去底座、支架和手柄，下列内容不得削去：
   - 每个分离部件（散落的骰子、旁边的硬币）；
   - 主体上部 40%（旗、硬币、王冠、火焰、顶上的骰子）；
   - 每个“奶油色岛”（浅色、低饱和的区域：骰面、纸、瓷器），保护范围为其外框外扩 4%·S 后与核的交集，需留住 95%；这样骰子的暗面也不会被切；
   - 粗子部件只能整块保留或整块舍去，不能切半。
5. **边距与边界**：每边留出边长的 6%；方框限制在图内，边长不小于 0.40·S。
6. **主体比最大方框还宽**：
   - 主体左右镜像对称（镜像 IoU ≥ 0.85，如扇、天平、双滚筒）时，方框居中；
   - 否则放在能完整容纳最多奶油色岛（骰面优先）的位置。

   这样 C08 保住船头和骰子，C13 保住骰子，C18 两个秤盘各留一部分。
7. **覆写表**：脚本内的 `OVERRIDES` 按主题分组，可以对个别 id 直接指定方框，见第 4 节。

开发中先后修掉的问题都是靠改方法解决的，没有用覆写：

- 早期只按质量收紧时，会切掉顶部的硬币、旗、骰子（C01、C03、C43）；
- C35 的小骰子被切半；
- U10 骰子底边被切；
- C08 的骰子被切；
- C18 只剩一个秤盘。

## 3 置信度含义

置信度是方法对“这个方框不需人工调整就能当作紧凑图标”的估计。它看不懂画面含义，只衡量下列风险。最终值为各项因子的乘积，凡是小于 1 的因子都会把原因写进 `note`。

| 因子 | 取 1.0 的条件 | 最低值 | 含义 |
| --- | --- | --- | --- |
| zoom | 裁切边长 ≤ 图长边的 0.85 | 0.7，裁切边长等于长边时 | 主体占满画布，裁切≈原图 |
| cut | 被裁掉的核 ≤ 12% | 0.4，裁掉 30% 时 | 主体被裁；主体比最大方框还宽时再乘 0.8 |
| fill | 轮廓占裁切面积 ≥ 30% | 0.6，≤ 12% 时 | 主体细长，32 px 下只剩线条 |
| split | 只有一组主体 | 两组 0.85，三组及以上 0.75 | 主体分成相距较远的几组 |
| detail | 96 px 渲染下细小深色点 ≤ 80 个 | 0.75，≥ 130 个时 | 32 px 下会糊成灰色，画面嘈杂 |

**分布**：

| 区间 | 数量 |
| --- | --- |
| ≥ 0.90 | 63 |
| 0.80–0.89 | 49 |
| 0.70–0.79 | 55 |
| 0.50–0.69 | 16 |
| < 0.50 | 1（C08，0.32） |

中位数 0.83。

**审查阈值**定为 0.80，低于阈值的有 72 项，都进入并排审查图。其中 36 项的唯一原因是“主体占满画布、裁切≈原图”。

**裁切边长**：

| 统计 | 值 |
| --- | --- |
| 中位数 | 0.926·S |
| ≤ 0.85（放大 ≥ 1.18 倍） | 34 项 |
| ≥ 0.95 | 68 项 |
| 最小 | C66，0.71 |

这批插画的主体本身约占画布的 85%，所以多数裁切只是去掉动作线和空白，放大有限。

## 6 AX-07 相似度（建议性，不是门槛）

**度量**：每张图标在纸色底上渲染成 32 px，计算三项距离，各自除以全部 16,836 对的中位数后取平均，1.00 表示一对普通的图标：

- 8×8 Lab 缩略图的平均 ΔE，反映颜色分布和粗略形状；
- 1 − SSIM（明度通道）；
- 主体颜色直方图的总变差距离。

前 30 对见 `similarity.txt`，并排图见 `similarity_pairs_*.png`。我对最接近的 5 对的判断：

| 对 | 距离 | 判断 |
| --- | --- | --- |
| C40 / C87 | 0.505 | **易混**：都是骰子沿斜阶向右上爬升，配色一样，32 px 下只差一条尺子的浅色带。两张都是控制器，可能同屏。 |
| U08 / U10 | 0.523 | **易混**：骰子在左下，红柄工具从右上插入，只有锤头和螺丝刀头不同。两张都是骰子升级，商店里可能同时出现。 |
| C119 / U10 | 0.533 | 轮廓相似。但一个是控制器，一个是骰子升级，很少同时以紧凑尺寸出现。 |
| C134 / I09 | 0.537 | 中等相似：上方都是深色圆形，下方是骰子。一个是控制器，一个是道具，对局画面上可能同屏。 |
| I11 / U10 | 0.568 | 中等相似：画笔的黄色颜料有助于区分。 |

## 8 需要决定

1. **运行时采样（影响最大）**：插画的导入设置为 `enableMipMap: 0`。用 `Sprite.Create` 从 1254 px 纹理直接画到 32–56 px，会出现噪点和断线。脚本额外输出 `sheet_32_paper_nomip_x2.png`，按“无 mipmap 时每像素一次双线性采样”模拟了这种效果。这是离线模拟，不是引擎截图。审查图使用面积滤波，代表的是理想效果。可选做法：
   - 为插画开启 mipmap，显存约增加 1/3；
   - 离线按本表烘焙小尺寸图标。
2. **边距的理解**：“6–10% of the side”现在按每边 6% 实现。若原意是两边合计 6–10%（即每边 3%），把 `MARGIN` 改为 0.03 后重跑并提交新表：
   - 中位数降到 0.87；
   - ≤ 0.85 的增至 79 项；
   - ≥ 0.95 的减至 19 项。

   另外，界面上给图标加内边距，效果等同于加大边距，所以表里的边距越小，界面的选择余地越大。
3. **非方形源图**：本表用每项自带的 `imageSize` 处理。另一种做法是把 11 张源图补成方形画布：表会更简单，C08 等也能完整显示，但需要修改美术文件。
4. **读取方式**：`crops` 是以 id 为键的对象，而 `GameTheme.cs` 使用的 `JsonUtility` 读不了字典，读取时需要能解析对象映射的方法。
