# P0-V10：三关周期、首领减益、50 张新控制器（p1.0.0）

状态：**IMPLEMENTING**（2026-11-14 起）。实施者不签署 ACCEPTED。

## 1. 目标与输入

- 目标：按 [规则规格](../specs/v10/RULES_SPEC.md) 与 [开发方案](../specs/v10/DEV_PLAN.md) 实现三关周期（普通 / 高压 / 首领）、39 个首领减益、首领战利品与商店赠礼组、50 张新控制器（C104–C153）、5 个道具、4 项骰面改造、3 项服务、关卡预览界面；逐卡测量强度后定价并校准关卡目标；发出 Windows 与 macOS 试玩包。
- 输入版本：p0.9.0（分支 `codex/v0.9`，提交 `31d3725`）；用户 2026-11-14 的 V1.0 指令（规格第 0 节原文）。
- 分支：`codex/v1.0`。
- 非目标：规格第 11 节。
- 工具：Unity 6000.6.7f1、.NET SDK 10、Python 3.11、本机 Codex CLI 的图像生成（经 `tools/art_gen/artgen.py`）。

## 4. 准备度检查（开工前）

- 规格：每张卡、每个减益效果、每个道具 / 改造 / 服务都有触发条件与数值；连带规则在规格第 8 节；黄金样例字段在附录 A。
- 接口：计分输入新增 8 个字段；计分输出新增封印、全局系数、骰面变更、扣款；存档结构 5 → 6。
- 调研（只读子任务 3 个）：界面改动点与全部按编号分支的位置；测试里钉住旧数值的断言；模拟器与美术管线。结论已用于方案第 4、7 节。
- 高风险项先试：
  1. 图像生成：先做 1 张代表图（C143 好事成双），参考图核对通过、与锚点并排风格一致后才启动批量。
  2. 规则核心改动后先在 .NET 宿主编译并跑旧测试：首次 364 / 373，9 项失败里 7 项是钉值、2 项暴露出“调试场景跳关时关卡类型不同步”，已改为一律从配置读取关卡类型。
- 验证环境：与 v0.9 相同。
