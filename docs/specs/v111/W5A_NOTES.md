## 1. 模型改了什么（`Fast.cs`）

**随机范围的变化**（都是扩大或新增，没有缩小、没有跳过任何卡）：

- 朝上面的引导形状从 12 种加到 13 种：新增“前四颗凑 4 点、接着两颗凑 1 点”（此时多数骰子保留标准六面，并给提交栏留够位置），否则 C155 的 ×4 档在 30 万例里几乎抽不到。原来 12 种形状的概率各自从 1/12 变成 1/13。

## 3. 机器人的新行为与近似（`Runner.cs`）

详细规则写在 `tools/balance_sim/README.md` 的“p1.1.1 的改动与测量”“成长卡怎么估值”“骰面改造与服务”几节，这里只列做法与它的近似程度。

| 机制 | 做法 | 近似 |
| --- | --- | --- |
| 成长卡估值 | 事件累计 + 每关事件数 × 增量 × 视野（6 关；下一关危险时 2 关），无上限；连庄按“同牌型 +0.1、换牌型减半”的期望迭代；抛光匠按“已过各关里刷新过最高单手的占比” | 平均速率、无方差；视野之外的成长不计 |
| 追赶值 | 估值用的候选卡继承报价上的 `growthCatchup` | 精确 |
| 乘法卡唯一 | 已持有的去重卡不估值、不买、不领 | 精确（冒烟里被拒命令 0） |
| 养成卡免栏位 | 用“买入后的卡列”调 `OrdinaryUsed` 判断放不放得下 | 精确；但不会为了免栏位去调卡列顺序 |
| 骰面改造 | 一笔两面；镀金用算式估值，其余实测；每店自选至多 2 笔（U06 / U08 / U03 / U04） | 镀金的算式忽略“权重变大挤掉别的面”；其余改造仍受 0.06 噪声门槛限制 |
| 牌型与颜色升级 | 估值不变，价格与上限读会话 | 只在实测增益过门槛时买 |
| 玻璃 | 实力估计里提交后 15% 碎、本关余下的手牌没有它；买脆化时按视野内存活时间加权“是玻璃的增益”与“少一颗骰的损失” | 入关实力不含“这一局永远少一颗骰”的长期损失 |
| 解锁（钥匙串 / C154） | 决策后逐颗试“放回这颗已锁骰”的决策价值；免费解锁涨 8%、钥匙串涨 20% 才用；钥匙串在金币超过计息上限或下一关危险时才买 | 前瞻不知道可以解锁；实际很少触发（见第 5 节） |
| C137 | 关内读真实点数；关外每模拟一关随机抽点数 | 关外是期望值 |
| C156 | 模拟的一关里按手牌顺序累计得分再比较 | 关外用下一关的普通目标（接高压或首领加目标时略偏） |
| 首领减益 B06 / B29 / B35 / B37 | 失效名单与预算读会话的入关预告；商店里用 `ControllerRules.DisabledBy`（游戏自己的函数）预估；成长减半走计分模型 | 没有自己复刻规则；`quoteMismatches` 为 0 |

机器人没有改的地方：手牌规划器的搜索（锁骰、提交、顺序）、买卖的阈值与留钱规则、高压接受规则、首领对策，都沿用 p1.1.0。

## 4. 新输出字段

全部在 `run` 的 JSON 里，字段表见 README 的“p1.1.1 新增的输出”。与交接包 C 节的对应：

| 交接包要的 | 字段 |
| --- | --- |
| 入关实力（平均手、第 25 百分位手，各 ÷ 目标） | `logs[].stages[].handMeanOverTarget`、`handP25OverTarget`（另有未除的 `handMean`、`handP25` 与 `subsBudget`；原有的 `power`、`safe` 是乘了提交次数的整关值） |
| 本关目标、实际总分、是否过关、几手、最高单手 | `target`、`score`、`cleared`、`subsUsed`、`bestHand` |
| 构筑快照 | `build[]`（定义、附魔、成长、追赶、牌面值、位置、明星点数、养成计数、是否免栏位）、`handLevels`、`colorLevels`、`goldStart`、`permanentDice`、`goldFaces`、`glassDice` |
| 成长卡贡献 | `growthShare`（仅首领关前；`实例:卡号 → 去掉它 ÷ 带着它`），汇总在顶层 `v111.growthShares` |
| 货架记录 | `shelf[]`（附魔、价格、是否买得起、是否去重卡）、`shelfGold`、`shopCycle`，汇总在 `v111.firstShelfByCycle` |
| 失败关号与类型 | `logs[].failStage`、`failKind`（原有的 `reached`、`fail` 保留） |
| 改造次数、镀金次数与花费（BX-14） | `upgrades[]`（每笔的改造、来源、面数、价格），汇总在 `v111.dieUpgrades` |
| 解锁次数 | 每关 `unlocksFree`、`unlocksKey`，每局同名字段，汇总在 `v111.unlocks` |
| 养成卡买入关与逐关改面数（BX-06） | 逐关的 `build[].cultivated`（入关时的计数；一张卡第一次出现在哪一关的 `build` 里就是买入后的第一关）加 `logs[].finalBuild[]`（终局计数） |

口径上要注意的三点：

1. `v111.firstShelfByCycle` 的附魔占比**包含**第 1、2 周期每批第一张不抽附魔的低价保底卡，所以会低于规格表里的概率（第 1 周期约 10% × 3/4）。要按规格口径统计，得从 `shelf[]` 里去掉每家店的第一张卡。
2. `growthShare` 用的是不带减益的平均实力；拿掉一张卡会改变百变模仿复制谁，这也算在里面。
3. `power ÷ target` 是“每手打最高分 × 提交次数”，而真实对局达标即停，所以 `score ÷ target` 与 `bestHand ÷ target` 小得多。两者不是同一个量。

`calibrate.py`、`make_targets.py`：`run` 的旧字段都没有改名，所以 `predict`、`solve` 的读法没有变；`summary` 多打印了诊断、失败关类型与每四关一段的中位数。`make_targets.py` 拒绝非 p1.1.1 的源配置与奇数目标，新增 `--keep-anchors`。三个模式与 `make_targets.py`（含生成的候选能被模拟器加载）都实跑过，见第 5 节。

## 6. 已知局限

**会低估实力**（真实玩家比机器人强的地方）：

1. 成长卡：6 关视野之外不计；对局里不配合养成（不为深蓝交全蓝、不为连庄保牌型、不为抛光匠冲高分、不为余勇可贾省提交），达标立刻结束本关。
2. 骰面培养：只用四种自选改造，只有镀金被稳定购买；不会围绕一个牌型把整套骰面改成型。
3. 牌型与颜色升级：没有“把一个牌型升到 12 级”的计划，只逐级看实测增益。
4. 解锁：规划时不知道锁可以撤；钥匙串买得晚、用得少。
5. 祭坛不买；光滑 / 粗糙 / 随机变形、遥控骰子等道具不用；养成卡的免栏位名额不主动利用。
6. 首领减益仍只影响当关打法，不影响长期构筑；高压挑战只看实力余量。

**会高估实力**：

1. 成长与骰面投影是平均速率，没有方差；连庄的投影假设相邻两手是否同牌型相互独立。
2. 镀金的算式没有扣掉“权重变大后别的面更少出现”的影响，对需要多种点数的构筑偏乐观。
3. 玻璃骰碎掉后“永远少一颗骰”的损失不在入关实力里（只模拟本关之内的碎裂）。
4. 入关实力按“每手都打最高分”估计，而且只抽 32 手；后期构筑单手分布很宽，单局读数噪声大。

**方向不定**：

1. 关外的 C137 用随机点数的期望，C156 用下一关的普通目标。
2. 机器人胜率不是玩家胜率（沿用旧版说明）。裸装起手，规划器的平均手约为精确动态规划最优值的九成（166–171 分对 184.6 分，小样本）。

## 7. 游戏代码疑点与没做的事

**没有发现需要协调者处理的游戏代码问题。** 300000 例对拍零差异；冒烟里会话没有拒绝任何命令，机器人按规则算出的预算与会话预告没有出入。几条观察，都不是缺陷：

- W3a 备注 N02 提到的 `ScoreBreakdown.colorMult100` 别名在当前代码里已经不存在（模拟器原先的 36 个编译错误里有几个就是读它造成的），与规格一致。
- 规则层的 `ValidateInstances` 接受两张同编号的去重乘法卡（`verify` 的随机构筑里有），这是规格 §9.3 说的“调试样例可保有重复”；正常局的限制在会话层，冒烟里没有出现重复的去重卡。
- 冒烟里初始货架的附魔占比按周期为 9%、17%、37%、38%、51%、57%、64%、61%（含保底卡，见第 4 节口径 1），与规格的 10 / 20 / 35 / 45 / 55 / 60 / 65 / 65 相比没有看出系统偏差；样本每周期 150–250 张，第 4 周期的 38% 对 45% 约在两个标准差上，只凭这 20 局不能下结论。
