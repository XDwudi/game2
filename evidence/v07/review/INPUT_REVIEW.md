## 实施时优先防止的风险

1. **规则与表现分离。** 保持 p0.6.0 / schema4、原配置及160黄金用例；新增表现收据只能读取冻结结果。跳过、暂停、读档、只读回放、音频随机都不得执行规则副作用或推进三条玩法 RNG。
2. **真实来源而非粗略命中计数。** 连锁 N 只统计真正产生计分作用的唯一控制器 emitter；C01 仅发币、满级 C43 无附魔、C45 无匹配、C53 抽到1等不能直接用 triggeredSourceIds 计数。C41 与目标身份分离，动态 owner 共享，附魔不复制。
3. **紧凑布局单位。** 1280×720 / 150% 时整个布局改用最终屏幕像素，提交区为 168 实际像素，K8 为4×2；不能继续乘一次 Canvas 缩放。每个交互热区至少40×40，主要动作固定可达。
4. **源文件与运行件。** 正式源入口为 ArtSource/Art07，运行件为 Assets/Art/Art07；71 图标指定 `.kra`，公共二维源另有62条 `.kra` 记录。程序点阵和符号允许保留脚本参数。若工作暂存在 art/v07，须由 root 明确正式路径映射，不能只交 PNG 或把 SVG 改后缀为 KRA。
5. **不能用风格遮住状态。** 红蓝点阵不被金层/玻璃/高光改色；黄金只作用目标面细边；临时、待选、已锁与纹理层可组合；红圆/蓝菱辅助不计入点数。材质与六个物理 faceId 独立。
6. **时间与并发预算是全手预算。** Normal ≤3.2秒、Fast ≤0.8秒；同阶段多个后置效果合并≤480ms；不是把每项300–420ms逐个追加。全局1主3辅优先于对象池容量。32卡必须合并焦点但保留完整来源明细。
7. **资源状态不得提前通过。** 原始224条均为 planned，四张图为 conceptOnly。制作清单可记录 produced/imported，但只有绑定真实引擎/构建证据才可 verified；保持原样规格不变，另建生产状态记录。
8. **双平台与旧失败。** 现有 v0.6 Windows 独占全屏、性能失败以及 Mac 实机未验仍是真实限制；本版 ART16/ART21 需各自新证据，不能从本次输入检查、离线 Blender 渲染或 Windows 推定通过。用户已同意 M5 人工测试，工具包可以为其准备。
9. **音频不是25个逻辑事件。** 16个逻辑 Cue 路由25条 WAV，Master/Music/SFX/UI 四公开组。基金卖价+3不发钱包到账音，普通关末不误播整局结束音。
10. **新 UI 状态需要全覆盖。** 设置新增文字缩放/辅助/质量/音频；调试工作区须先保存普通检查点并建独立副本，第一次修改才标 debug；S19引导不得偷偷改变骰面或赠资源。不能把已有 v0.6 功能直接称为新22屏全验收。
