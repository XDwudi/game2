# 美术流程校准试验（2026-11-14）

用途：验证 Claude Code 能否经本机 Codex CLI 调用 GPT 内置图像生成，并比较“直接提示”与“标准流程”的风格一致性。**两张图都不是游戏内容，不得导入工程。** 主体相同（铜闹钟 + 一颗陶瓷骰子），唯一变量是流程。

| 目录 | 做法 | 实际结果 |
| --- | --- | --- |
| `naive-probe/` | 手写提示词，`codex exec -i` 附上 C29 作为风格参考 | Codex 会话日志显示图像调用**只传了文字提示，没有传参考图**（无 `referenced_image_paths`），参考被静默丢弃。琥珀色 0.23（锚点范围 0–0.10），石油青阴影面偏少。输入约 14.7 万 token（代理先去读了 imagegen 技能） |
| `clock/r01/` | `tools/art_gen/artgen.py generate`（kit style-kit-1）：风格样板图 + 固定提示段，事后从会话日志核对调用 | 核对通过：生成记录显示模型收到了样板图（SHA 一致），提示词逐字一致，透明已请求（artgen-1.1 的 `recheck` 复核仍通过）。输入约 5.8 万 token；周额度 77% → 78% |

指标对比（直接提示 → 标准流程）：

| 指标 | 直接提示 | 标准流程 |
| --- | --- | --- |
| 深色（石油青与墨） | 0.28 | 0.38 |
| 金色 | 0.230 | 0.257 |
| 象牙 | 0.380 | 0.318 |

只有深色占比改善了；金色两张都偏高，因为主体都写了“brass alarm clock”（铜闹钟），主体描述本身指定了颜色。观感上，标准流程那张的阴影面与骰子画法更像锚点，但这是实施者的自评，而且每种做法只有一张，不能当作流程更一致的证据。

教训已写入流程：主体描述只写物件与动作，不写与色彩角色冲突的材质颜色；确需金色主体时，由复核者记录理由。

版本说明：`clock/r01` 由 artgen-1.0 生成。那一版在 Windows 上以 CRLF 写 `prompt.txt`，而 record 里的 `imagePromptSha256` 是按 LF 文本计算的，所以与文件字节的 SHA 不一致；artgen-1.1 已改为按文件字节记录。两张审查单的范围列用的是 8 个锚点，不是现在的 71 张参考集。r01 使用的 style-kit-1 原文件当时被就地升级、没有留档；后来从 1.1 反推重建，逐字节与 r01 记录的 SHA（ecabad40…）一致，存于 `ArtSource/StyleKit/history/style_kit_style-kit-1.json`。

文件说明：`original.png` 为工具返回原图的逐字节副本；`record.json` 含提示词、参考 SHA、Codex 版本、线程 ID、调用核对、额度与 token；`review_sheet.png` 为一致性审查单（纸/毡底、实际显示尺寸、与 8 个锚点同尺寸并排、漂移指标）。`naive-probe/codex-events.jsonl` 删去了代理读取的上游技能全文，其余事件原样保留。

结论范围：证明调用链可用，也证明校验能发现“参考图没传”这类静默失败。“标准流程更一致”目前只有一张图的自评，未经证实。不证明锚点已获用户认可，也不代表任何内容插画已通过验收。
