# art0.7.0 production sources

These are original project drawings and geometry, produced from the user's v0.7 specification. The four concept images remain reference-only; no pixels from them were cut into runtime assets. Dynamic UI words, prices, counters and multipliers are not baked into content images. Review status is **generated, pending actual Unity visual review**, never automatically verified.

## Sources and reproduction

- `tools/art_v07/build_art_samples.py`: four representative controller icons C02, C41, C45, C52, shared background/card/button/badge templates. Hand-composed layers on a 64-pixel logical grid, nearest-neighbour 256-pixel exports. `ContentIcons/Controllers/*.kra` are real Krita files with 4–5 named editable paint layers; corresponding OpenRaster intermediates preserve reproducible layer names.
- `tools/art_v07/build_content_icons.py`: the complete71 explicitly composed content icons, expanded after the root reviewed the four cards in the actual running battle interface (`golden-sample03`). `--only C35` is available for isolated revisions. The expansion applies one identical guard-band transform to every new illustration; it never auto-fits individual silhouettes. Static illustration marks such as the1/3/6 tickets or the20-point coupon follow the specified motif; live scores, current n, prices, levels and actual die faces remain engine UI/data.
- `tools/art_v07/build_public_symbols.py`: 28 individual common action/status symbols. These intentionally use exact code-native geometry rather than generated imagery.
- `tools/art_v07/build_dice_textures.py` or `Scripts/generate_dice_pips.py`: exact standard 1–6 pips in red and blue, 1024 atlas plus individual 256 images, protected rough/smooth/gold masks and seven shared FX textures. Mask values are in alpha; RGB is white, except the background vignette. Import masks as linear data, not sRGB color.
- `tools/art_v07/convert_krita_sources.py --krita <path/to/krita.com>` converts `.ora` to `.kra` using the official CLI, then checks actual Krita ZIP/layer structure. Run with the working directory set to the binary's `bin` directory (the script does this). Krita 5.3.4 portable was downloaded from the official KDE archive; SHA256 `4bf5b51100b30fa68edd12b995932b82f8a0080ef115b5461941fa2d186d126c` matches the official mirror-list value. The tool installation is a workspace cache and is not part of the game.
- `Blender --background --factory-startup --python tools/art_v07/build_dice.py`: one centered 1-unit beveled body, six named faces, independent face mesh, six fragments and animation intermediates. Blender 5.2.3 LTS / `e13b728c6880`; FBX exporter properties are checked before running. No third-party model/add-on is used.
- `tools/art_v07/render_dice_review.py`: actual Blender source previews (six directions, ceramic/glass/gold). They are **not Unity screenshots**. The preview material is illustrative PBR; the shipping three-tone shader and final camera belong to Unity integration.
- `tools/art_v07/validate_art_samples.py`: exact pip connected-component count, Krita/PNG visible-pixel and alpha consistency, dimensions,24-pixel content margins,71 unique stable IDs, model budget/opposites. Failed records remain under `Review/`; this source check is not user or visual acceptance.
- `tools/art_v07/roundtrip_krita.py --krita <path>`: actually reopens every content `.kra` in Krita and exports it again, comparing visible pixels and alpha to the runtime image. `tools/art_v07/verify_dice_source.py` reopens the actual `.blend` and samples transforms and six normal anchors. Both bind report records to source hashes.
- `tools/art_v07/inventory_art.py`: all 224 planned resource records, including the one optional LOD. It records exact file presence/hashes without promoting any record to imported or verified. Root supplies real engine/visual evidence later.

## Import handoff

Runtime paths use `DicePrototype/Assets/Art/Art07`, matching the user manifest. Stable IDs come from the original JSON, not names or list positions. Sprite PPU100; Point, no mipmaps, clamp, sRGB for pixel art, uncompressed initial baseline. Bilinear for soft FX/vignette/contact shadow. Felt/grain repeat. Straight alpha exports have RGB bleed; opaque text belongs to TMP above these images.

Slice borders: button16 all sides, standard/modal panels24, card/compact-card16, slot/focus16, tooltip24, progress12 left/right. Focus and dice/inventory slot textures have transparent centers so they can overlay actual 3D dice. Draw fill as a separate UI layer when needed.

`Dice/Models/dice_body_bevel.fbx` has188 triangles,96 vertices,1×1×1 bounds; bevel0.055/3 segments. Fragments total120 triangles. Six named `Face_F01`…`Face_F06` anchors preserve identity while the point/color/texture/gold parameters change. Final Unity axis and size still require actual importer checks. `Dice/Data/dice_face_map.json` is authoritative; the old first-sample root-directory JSON is awaiting root-controlled migration to preserve any imported GUID references.

The two roll FBX animations are0.90 seconds,30fps, frame1–28; rotation is result-aligned throughout the final120ms. Lock/submit sample clips are0.20 seconds and may be retimed by the frozen presentation config. `dice_break.fbx` contains six separate fragment trajectories with last motion key at0.45 seconds; FBX integer export extent is0.4667 seconds. Extract to the manifest's `FX/Animations/*.anim`, trimming break to0.45 seconds. Animations never determine faces, destruction, rewards or any other rule result.
