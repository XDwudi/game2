# v0.9 平衡模拟证据

工具：`tools/balance_sim`（说明与机器人的已知盲区见其 README）。机器人、种子（5000–5299，共 300 局）与 v0.8 的测试相同。

| 文件 | 内容 |
| --- | --- |
| `verify_p090.json` / `.log` | 快速计分模型与真实 `ScoreCalculator.Evaluate` 对拍 30 万次随机提交：0 差异；43 张计分类新卡每张都有“出现”和“触发”的样本。在最终源码上重跑过 |
| `cards_p090.json` / `.log` | 每张控制器在两个参照构筑里的等效倍率与触发率；成长卡各列成长 0 与一个注明的中期成长值 |
| `run_p090_shipped.json` / `.log` | 校准前的目标（第 12–24 关 38,000 … 4,000,000，即 v0.8 实测时的备选数值）：通关率 43.7%，最后一关实力 ÷ 目标 7.8，后段过易 |
| `run_v09_t1.json` / `.log` | **最终目标**（46,000 … 15,000,000，候选 `tools/balance_sim/candidates/v09_t1.json`，与游戏配置的关卡目标逐项相同）：见下 |
| `run_p090_final.json` / `.log` | 在最终源码与最终配置上的复跑（存在时以它为准） |

命令：

```powershell
dotnet build tools/balance_sim/BalanceSim.csproj -c Release
dotnet tools/balance_sim/bin/Release/net10.0/BalanceSim.dll verify --n 300000 --out evidence/v09/balance/verify_p090.json
dotnet tools/balance_sim/bin/Release/net10.0/BalanceSim.dll cards --hands 3000 --threads 8 --out evidence/v09/balance/cards_p090.json
dotnet tools/balance_sim/bin/Release/net10.0/BalanceSim.dll run --first 5000 --seeds 300 --threads 8 --out evidence/v09/balance/run_p090_final.json
```

## 最终目标的结果（`run_v09_t1`）

| 指标 | p0.8.0 实际 | 校准前（终点 400 万） | **p0.9.0 最终（终点 1500 万）** |
| --- | --- | --- | --- |
| 通关率 | 40% | 44% | **26%** |
| 死亡分布（每四关一段） | 25 / 24 / 19 / 15 / 7 / 9 % | – | **19 / 24 / 10 / 13 / 19 / 15 %** |
| 第 13–24 关逐关通过率 | 94–99% | 95–99% | **89–97%** |
| 最后一关 实力 ÷ 目标（中位） | 6.2 | 7.8 | **3.1** |
| 关始金币（第 9 关起） | 21–30 | 19–45 | **19–37** |
| 通关局控制器数 / 普通栏位 | 8.7 / 4 | 9.9 / 6.8 | **9.8 / 6.8** |
| 每局购买“扩充栏位” | – | – | **1.03 次** |
| 通关构筑出现率最高的卡 | 百变模仿 44% | – | **熟能生巧 45%、错乱乘积 44%、收藏家 41%** |

规划器自检：6,346 次真实提交（不含错乱乘积的构筑），规划器预估的分数与会话实际结算的分数 0 次不一致。

## 逐卡观察（供设计参考，没有据此改数值）

- **偏强**：便宜的成长加分卡在基础分低的前中期很强——熟能生巧（普通 3）成长到 +50 时等效 ×2.4–4.1，积少成多 +40 时 ×2.1–3.4，余勇可贾 +32 时 ×1.9–2.9；双刃剑（稀有 6）等效 ×2.7。
- **在机器人手里用不起来**（它不会为这些卡改打法或改骰子，不能据此判断强弱）：散兵游勇、顺水推舟、杂牌军、三三得九、场外红人、幕后推手、空城计；依赖骰面改造的纹理大师、纯色主义、始终如一、金玉满堂；精兵简政（它不删骰子）；祭坛（它从不购买）。
- 经济卡（铁饭碗、利滚利、以战养战、砍价高手、聚宝盆）不计分，等效倍率恒为 1；它们的价值只体现在整局模拟里。

## 局限

机器人通关率不是玩家通关率，只适合比较两套数值。它不经营养成型打法，对局中也不会为了成长卡改变出牌；成型流派（小点数、红组、留池、顺子等）的真实上限没有被模拟覆盖。校准后段目标的子任务因用量上限中断，只跑了一个候选（它已满足预设目标），没有做多候选比较。
