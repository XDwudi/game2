## Root-owned physical-pip, hover and remote-observation changes

**Pip helper:** inspected `DiceTable.MakeFace`, `VertexFace.shader` and revised `ConnectedMeshComponents`. The mesh really contains a separate outline and white fill for each pip, plus non-white gold/texture geometry. The old disconnected-surface count therefore counted a one-pip face twice. The revised helper counts connected triangles whose vertices are actual pure-white pip fills; it does not read a mesh name or assume a fixed triangle count. Exact expected pips and >.999 orientation remain, and coverage increases to **6 pips × 2 gold states × 3 textures = 36 physical configurations**, plus remote F01 showing six while permanent value remains one. This is a valid geometric semantic correction, not changing expected one to two. The shader tints neutral RGB-equal vertices generally; the helper's selection is specifically the authored pure-white pip fills. It is not a claim that the shader tints only white, nor a replacement for GPU visual contrast checks.

**Hover timing:** old nominal 150ms waiting could resume after 300ms on a slow rendered frame. New wrappers preserve original show/hide callbacks and record actual Unity unscaled callback timestamps. Tests require no early show before 300ms/no early hide before 60ms and completion by the first frame after each deadline, plus real tooltip existence. This is a more direct observation with unchanged production deadlines, not a threshold relaxation. It cannot establish realtime frame performance by itself.

**Remote break:** replacing the removed Toast with ActionReason count/capacity text retains the lost D001 ID in the actual committed DieBroken receipt, no replacement/refund, surviving target values, unchanged permanent faces and effective C12 conversion. The new feedback is checked after Skip reaches the stable final view. No rule validation was removed.
