**粗体的合成。** TMP 先在字重表指向的粗体资源里找字，找不到就回到常规体资源及其回落，这时 `isUsingAlternativeTypeface` 为假，TMP 用合成粗体（`TextMeshProUGUI.cs:3166–3175`）：笔画按材质加粗，字距加 `boldSpacing`。DiceChineseBold 只有 844 字，游戏会显示的 1,027 个字符里有 215 个不在表内，其中 157 个出现在配置的名字里。结果：184 个卡名里 87 个、39 个首领名里 35 个至少有一个字是合成粗体，例如 C76“越挫越勇”四个字全是，C88“杂牌军”的“杂”“军”是、“牌”不是，B03“苛税”、B11“厚墙”两个字都是。我没有在截图里逐字核对它们的观感（§10.3 R10）。

**可读性。** `legibility-720p.png` 与 `legibility-1080p.png` 把各角色的样例字串按 720p 与 1080p 的实际像素渲染（FreeType，不是 TMP 的 SDF，只看笔画）：

### 3.3 回落链（提案）

- 标题字资源的回落表：`[DiceChineseBold, DiceChinese]`。
- 上表里的每个符号（· → ← ↑ ↓ ≈ ≤ ≥ ✓ × − … [ ]）都在 DiceChineseBold 的 844 字静态表里（逐个核对），画出来是 Noto Sans SC Bold 的真粗体字形。因为标题字的字是 Normal，回落的字不会再被合成加粗。
- 第二项 DiceChinese 兜底：它的回落表接着是动态的 DiceChineseFallback，覆盖 Noto Sans CJK SC 的任何字，所以标题角色里不会出现缺字方框。
- TMP 在找回落时，回落资源自己的回落表也会被找（`TMP_FontAssetUtilities.GetCharacterFromFontAsset_Internal` 的递归），但字重表指向的粗体资源只找它自己的字表，不找它的回落表；这就是 §3.4 的问题。
- 回落字形的行高与基线：标题字资源的上下沿与基础字体相同（§5），所以一行里出现回落的“·”时，行的高度与位置不变。

### 3.4 粗体字表补齐（Q5）

§1.4 的合成粗体问题与标题字无关，但它落在本稿的几个角色上：默认与瑞士的全部标题角色、唐三彩与黑金的卡名与分区标题条、漫画的卡名，用的都是基础粗体。提案（Q5 选 A）：

- DiceChineseBold 的字表改为“游戏会画成粗体的全部字”，用 §4.1 同一个字表工具生成（实际取 1,027 字的全集最简单，约 1.2 张图，按 2 张算）；
- `V071FontSetup` 现在要求粗体字表与常规体完全相同（`V071FontSetup.cs:32、137–139`），改为按生成的字表校验；常规体 DiceChinese 不动（常规体缺的字由动态回落画，字形与静态表一样，没有观感差别）；
- 代价：显存 +4 MiB（可读时 +8），包体约 +1.2 MB；默认与瑞士的卡名、首领名、标题里表外的字（标题角色用到的字里约 160 个）的像素会变（从合成粗体变真粗体），像素对照的基线要重拍。

### 4.2 风格怎么指定字体

theme.json 加一个可选的 `fonts`（提案）：

```json
"fonts": {
  "title": "Fonts/title",
  "roles": ["screenTitle", "stageNumber", "bigNumber", "bossName", "primaryButton", "sectionTitle"]
}
```

- `title`：风格目录下的 Resources 路径；`roles`：哪些角色用它，取 `screenTitle`（T1）、`sectionTitle`（T2）、`stageNumber`（T3）、`bigNumber`（T4）、`cardName`（T5）、`bossName`（T6）、`primaryButton`（T7）。不写 `roles` 时取 T1、T3、T4、T6、T7。
- 不写 `fonts`（默认、瑞士、测试用风格），或资源载入失败：所有角色用基础字体加粗，就是今天的样子。载入失败时打一次警告；`tools/art_v11/theme_contract.py audit` 把 theme.json 写了却找不到的 `Fonts/title` 列为 FALLBACK，严格审计判失败。
- 不选代码表（按风格 id 写死在代码里）：THEME_SPEC 的约定是每套风格的选择跟着风格走，测试用风格（`GameTheme.CreateForTests`）也能带字体；代码表每加一套风格都要改代码。
- 不放进色板：`ThemePalette.Hexes`（`UI/Theme/ThemePalette.cs:47–53`）只收颜色，`fonts` 是 `ThemeFile` 的另一个字段。
- 四套的 theme.json 都由各自的生成器写出，且有“与重新生成一致”的测试（STATE，W20Y 合并步骤第 2 条），所以 `fonts` 要加在生成器里，不能手改。

载入：`GameTheme` 的 `ThemeFile` 加 `fonts`；`EnsureLoaded`（`GameTheme.cs:86–96`）里载入 `TitleFont`，与界面件、桌面图一样载入后保留（W22i 只在换风格时释放卡牌插画，`GameTheme.cs:120–136`）。`ApplyTheme11`（`GameApp.Theme11.cs:22–29`）在 `ThemeRegistry.Activate` 之后设置 `UiKit.TitleFont` 与 `UiKit.TitleRoles`，再重画。

## 5 度量

TMP 用字体资源 Face Info 的上沿、下沿算行盒（`TextMeshProUGUI.cs:2963–2964、3260–3267`），用 Baseline 移动字形而不改行盒（`:2968、3190`），用 Scale 缩放整款字（`:2953`）。马善政、站酷快乐、站酷小薇三款的行高只有 1.0 em（上沿 0.88、下沿 −0.12），而代码的框高与行距都按 Noto 的 1.448 em 定（§1.4）。不统一的话：单行字在框里的垂直位置会变；多行标题按 1.0 em 排，配上代码的负行距（−8 到 −16）会叠行；一行里出现从基础粗体回落的“·”时，行盒按 Noto 的上下沿长高，同一个标题带不带“·”位置不同。

提案：四款的 Face Info 都设成与基础字体相同的行高 1.448 em、上沿 1.16 em、下沿 −0.288 em（按各自的采样字号换算成像素），再用缩放让汉字墨迹的高度接近基础粗体，用基线让墨迹中心对齐基础粗体的 0.380 em。量自 §3.1 的标题字表（524 个汉字，`role-coverage.json`）：

# 第二部分 卡面断行

## 7 现在的问题

### 7.1 TMP 怎么断行

TMP（ugui 2.6.0）在这些位置记“可断点”（`TextMeshProUGUI.cs:4404–4465`）：

1. 空白、零宽空格、连字符“-”之后；
2. 一个中日韩字符之后，除非它是“不能放行尾”的字（左括号、左引号等），或下一个字是“不能放行首”的字（，。、）等）；
3. 一个非中日韩字符之后、下一个是中日韩字符时，例如“1金币”的“1”之后；
4. 一行的第一个词就放不下时，任意字符之后。

TMP 不认识词，所以“金|币”“红|骰”“锁|定”“对|面”都是可断点；数字与单位之间（“−1|点”）也是。另外 TMP 判断“中日韩字符”的范围不含全角标点 FF01–FF64（`TMP_TextParsingUtilities.cs:262–317`），所以“（”后面接汉字时，第 3 条让“（”之后成为可断点，行尾会留一个左括号。

现有的补救是 `BalancedLines11`（`Play11.cs:789–823`）：只处理两行，在离中间最近的标点或“ · ”处断开，没有标点时在“最平衡的字”处断开，每行至少三个字。它用在提示行（`Play11.cs:774`）、引导（`Art07Guide.cs:237`）、本关牌的首领效果与通关奖励（`Play11.cs:337`）、商店顶栏中间一行（`Shop14.cs:168`）、货品行的短文（`Card11.cs:406–410`）、货品行的长卡名（`Card11.cs:376`）、选面的提示与骰子名（`ShopFacePick14.cs:255、278`）。它的“最平衡的字”仍可能断在词里。

没有用它的：商店与桌面尺寸卡的短文（`Card11.cs:295–312`）、文字卡的短文（`Card11.cs:387–392`）、迷你卡的短文（`Card11.cs:399–412`，不是货品行时），以及选面面板里除提示外的各行（`ShopFacePick14.cs:250–256` 的 `Line(…, balanced=false)`：S1 的短文、S3 的变化、说明、原因、价格）。这些都由 TMP 自己断。

### 7.2 测量方法

截图只覆盖一部分卡（卡面画廊每种稀有度只放短文最长的 8 张），所以用模拟统计全部 184 张，用截图核对模拟：

- 文字栏宽：按 `DrawTallCard13`、`DrawCompactCard13` 的算法，从各风格的卡面贴图量出画出的边框（`FrameInsets11`、`RingInsets13` 的同一算法），得到商店尺寸的文字栏宽：默认 170.5、瑞士 184、唐三彩 180、漫画 186、黑金 185、彩绘玻璃 184 单位；桌面尺寸 216 宽时 171.5–182，7 张卡时再窄 19.4；文字卡（150%）247–262。同一段短文在不同风格里断法不同，原因在这里（短文本身四套都用基础字体）。
- 字号：照搬卡面的适配循环（插画先让到 72 / 56，再把短文从 20×比例降到 19.5，放大文字时再让卡名降到 19.5，最后插画降到 40）；文字卡照搬 TMP 的自动字号（19.5 到 30）。
- 断行：照搬 §7.1 的规则，字宽取 Noto Sans CJK SC Regular 的字形表（DiceChinese 与它的动态回落是同一款字）；不计字距微调。
- 场景：商店尺寸（价格按钮一行“购买”，以及 E1 的最坏情形——两行的“卡牌已满 10 张”）、桌面尺寸 216 宽与 7 张卡、文字卡 150%、选面面板（440 宽）。不含数值角标把附魔角标挤到卡角、卡名因此缩小的情形（那时短文的空间更大，字号可能更大）。

核对：W13 画廊的默认商店尺寸 100%（16 张）、默认桌面尺寸 7 张卡（24 张），W22i 画廊的漫画商店尺寸 150%（价格一行、没有角标的 9 张），共 49 张卡逐行相同、0 处不同；STATE 里的五个例子全部复现：瑞士 C01“每次提交后获得1金 / 币。”、C02“提交的骰子里没有红 / 骰时，得分×3。”，默认 C05“若只剩1~2颗没锁 / 定”、C37“…永久−1 / 点。”（C36 的“+1 / 点。”同样），选面 U11 说明 150%“把这一面的点数和颜色复制到对 / 面”。（STATE 写的“永久-1”在配置里是全角减号“−”，TMP 的断法相同。）

“坏断行”的口径：

1. 断在词里：本稿的词表草稿（`lexicon-draft.txt`，起草时人工判词，266 词：骰子、金币、红骰、提交栏、永久骰、对面、朝上、获得、容易……），加汉字数字带量词（一颗、两颗、第二颗、六个、三选一），加“每、第、这、那、各”放在行尾；
2. 断在数字里，或数字与它的单位之间（点、颗、张、件、次、格、关、级、层、个、面、手、种、倍、家、项、金币、%），或行尾是运算符（+ − × ÷ → ~ ≤ ≥ ≈ =）；
3. 行尾是左括号或左引号；
4. 末行只有一个字（标点不计）。

另外单列“末行只有两个字”（如“×3。”“计算。”），算不平衡，不算坏断行。第 1 条依赖词表，第 2–4 条不依赖。

## 8 断行规则（提案）

### 8.1 规则

`WrapLines21(label, text, width, maxLines)`：用 `label` 当前的字体与字号量字宽（同 `BalancedLines11` 的 `GlyphAdvance11`），返回插好换行的文字；在 `maxLines` 行内找不到合格的断法时返回空，调用处退回 TMP 自己断行并在开发日志里记一笔。

**不拆开的单位**（断点只在单位之间）：

| 单位 | 例 |
| --- | --- |
| 词表里的词 | 金币、红骰、锁定、对面、朝上、基础分、提交栏、永久骰、三条带一对、依此类推 |
| 数字连同符号与单位 | “+15%”“×1.5”“−1点”“1~2颗”“50%→65%”“2-5-2”“≤13”“第2颗”“+3金币”“Lv.0” |
| 汉字数字带量词 | 一颗、两颗、第二颗、六个、三选一 |

**行首行尾：** 行首不放收尾标点（，。；：、！？）”…）；行尾不放左括号、左引号、运算符（+ − × ÷ → ~ ≤ ≥ ≈ =）、“每第这那各”。“ · ”分隔处可以断，断开时去掉分隔符（同 `BalancedLines11`）。

**末行：** 至少两个字（标点不计），所以不会有孤字。

**选择顺序：** 在上面的约束下：

1. 行数最少；
2. 不在词内断（见 §8.3）；
3. 末行至少三个字；
4. 尽量不违反“风格”规则：短括号（括号里不超过 8 个字、没有逗号分号）放在同一行；介词“从按比向为由到约”跟着后面的数字；“×1起”“+0起”的“起”跟着数字；“时”不放行首；
5. 在标点处断的多；
6. 最长的一行最短（平衡）；
7. 末行最长。

第 3、4 条只在行数相同的断法之间比较，不会因此多出一行。

### 8.2 词表

- 放在 `Data/LineBreakWords.json`（字符串数组加版本号），启动时随配置读入；`WrapLines21` 与 `BalancedLines11` 共用。
- 来源：本稿的草稿（`lexicon-draft.txt`，266 词，起草时人工判词）作起点。实施时用工具 `tools/v21_linebreak_words.py` 列出候选：配置的全部短文（184 张卡、39 个首领减益、6 种战利品）与选面文字，在代码用到的每个宽度与字号下，规则会用到的每个非标点断点两边的字；人工复核（文字复核可交 Codex 只读或用户），确认后写入词表（Q7）。
- 测试：词表里每个词至少出现在一段文字里（没有死条目）；每段文字在每个宽度下的非标点断点写进报告，复核时看。

### 8.3 放不下时

规则偶尔要多一行，现有的适配循环按原来的顺序吸收：插画先让到 72（商店尺寸）或 56（桌面尺寸），再让短文降到 19.5，放大文字时再让卡名降到 19.5，最后插画降到 40（`Card11.cs:298–312`；CARD_TEMPLATE §9 第 11 行）。循环里每试一个字号，都量断好行的文字的高度，而不是 TMP 自己断行的高度。

到插画只剩 40 仍放不下时，按剩下的高度定 `maxLines`，再依次放宽：先放宽“风格”规则；再允许在词内断，但仍不在数字与单位之间、运算符之后、左括号之后断；仍不行才退回 TMP 自己断行，并在开发日志里写下卡、宽度与字号（`W21_WRAP_FALLBACK`）。

文字卡（150%，`Card11.cs:387–392`）现在用 TMP 的自动字号，改为自己选字号：在 19.5 到 20×比例之间按 0.05 一档（与 TMP 自动字号的精度相同，§8.5 的模拟也是这样）从大往小，取断好行后放得下的最大字号，关掉自动字号再设字。迷你卡（`Card11.cs:399–412`）照旧只在放得下时显示短文；货品行的两行短文改用 `WrapLines21(…, 2)`。
