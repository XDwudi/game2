## 2 全局原则（任何资源都不能违反）

1. **高清锐利。** 按原生分辨率绘制，或用矢量超采样后缩小。禁止低分辨率放大、抖动和整屏像素化。依据：用户 2026-11-11 否决像素方向，原话是“这个完全是糊了”。阶梯切角是造型，不是像素化。
2. **主题层与规则层分开。** 插画和图标不烘焙卡名、数值、价格、倍率、附魔、状态或按钮。精确骰点和牌型示例由引擎生成。主标题字标是唯一的固定文字例外。
3. **一个色板。** 只用 §3 的色值。新增色相需要用户决定。图像生成的局部偏色在引擎内不会被修正，因此插画必须靠参考和审查控制颜色。
4. **三种表面层级。** 沉入桌面的信息层、放在桌上的内容层、可按下的动作层，所有页面共用（v071 §05）。
5. **光从左上。** 界面件的投影在右下，硬边。插画的阴影面也是硬边，只在阴影面里加网点。
6. **同类共享。** 同类资源共用同一卡框、组件、状态层和材质。页面不得自建一套画法。

## 4 内容插画规范

适用于 P0Config 中 `controllers`、`consumables`、`services`、`diceUpgrades` 的卡面主题图。下列中文要点概括 style_kit 中的英文固定段，措辞以 kit 为准；修改任何一方都需要新的 kitVersion。

### 4.1 画法

- 高清限色丝网印刷风格：粗而均匀的深石油墨描边，大块平涂色面。
- 每个形体有一块硬边阴影面，细网点只出现在阴影面内，另有小而利落的象牙色高光。
- 光从左上，物件为三分之四俯视角。造型敦实、简化，略带玩具感。
- 陶瓷骰子是圆角暖象牙立方体，骰点为墨色。只有卡牌机制本身涉及红蓝时才画红点或蓝点。这是从 71 张已交付插画归纳的惯例；游戏内的 3D 骰子仍按 v071 §05 使用红蓝珐琅点，两者不冲突。

### 4.2 色彩角色

画面以象牙色（受光面）和石油青（阴影面、底座、深色部件）为主，墨色用于轮廓与骰点。红、蓝、金只作点缀，每种只占几小块，金色只给硬币、黄铜、奖励或单个高光。不用其他色相，不用渐变，不发光。

实测占比如下。`artgen` 审查单用“71 张已交付”一列定位漂移，**不是**通过门槛：

| 角色 | 8 个锚点 | 71 张已交付 |
| --- | --- | --- |
| 深色（墨与石油青） | 27%–59% | 23%–66% |
| 象牙 | 34%–53% | 22%–58% |
| 红 | 0–24% | 0–44%（C25 最高） |
| 蓝 | 0–25% | 0–45%（U05 最高） |
| 金 | 0–10% | 0–10%（C01 最高） |

红色或蓝色本身就是主体时（缎带、冰块），可以超过“点缀”；金色在全部已交付插画里从未超过 10%。

### 4.3 构图与交付

- 交付 1254×1254 RGBA 正方形透明原图。
- 每张最多三个物件，组成一个整体剪影。主体宽约占画布的 70%–95%（71 张实测 68%–98%，锚点 73%–90%），四周留均匀透明边，不贴边。v071 §05 的“70%—85%”量的是插画窗口，口径不同。
- 64 px 下仍能认出主体。
- 可在主体左上加两到三笔短动作线或一个小火花，表达“触发”或“作用”。通常是青色；红色或深色主体也用红色或墨色（锚点 C48、C03 为红色，C01 为墨色，C42 为金色火花）。多数现有插画有这组动作线。

### 4.4 主体描述的写法

主体描述（job.json 的 `subject`）是每张图唯一可变的部分：

1. 只写物件、动作和物件之间的关系。不写颜色和材质色，例如写“闹钟”，不写“铜闹钟”。只有机制本身要求时（红骰、金币）才写颜色。2026-11-14 的校准试验就是因为写了“brass”，金色超出了锚点范围。
2. 隐喻要直白，一眼能联想到卡牌效果（取自 P0Config 的 `description`），但不画成规则示意图：不画精确牌型，不画数字。
3. 一张图一个概念。先查看现有 71 张的总览，不与已有主体撞车。
4. 原创。可以借鉴机制思路，但不画任何现成游戏的卡面、角色或标志物。

### 4.5 禁止

文字、字母、数字、标签、价格、卡框、界面元素、纸张或彩色底、地面场景、棋盘格、物件下的投影板、写实或 3D 渲染感、柔和喷枪渐变、像素画、霓虹光、做旧与破纸边、人物和表情化的脸。

## 5 界面件、图标、骰子、桌面与特效

这些资源有精确尺寸或规则约束，**不用 GPT 生成成品**（可以用 GPT 出概念草图，再按脚本实现）：

| 类别 | 现行规则（详见权威源） |
| --- | --- |
| 界面表面件 | 每角两级阶梯切角，每级 6 参考单位（PPU 200 下为 12 px）；九宫格边距 40 px；墨边 2.5 单位；右下硬投影；以白或灰绘制，由代码按语义上色；4 倍超采样后缩小。见 v073 ART_PLAN §1、§2 |
| 功能图标 | 96 或 128 px，平涂，墨线，光从左上，与 v0.73 的 `ui_icon_*` 同一画法；色与形双重表达，不只靠颜色 |
| 骰子 | 唯一一颗 Blender 母模，各页面共用；面材质（光滑、粗糙、黄金、玻璃）由着色器表达；点数保护区内不放装饰；不用任何生成图冒充游戏内骰子 |
| 桌面、字标、卡背 | v0.72 矢量；桌面不放与界面争抢的图案 |
| 特效 | 白色绘制、代码上色；受“减少动态”控制；粒子不遮挡点数与总分 |

## 6 在游戏里怎么看

任何资源的风格结论，都要在真实游戏画面里，和相邻的同类资源放在一起看：

- 插画在三处看：商店卡、详情、紧凑槽位；
- 界面件在 1920×1080 与 1280×720 下看；
- 同时在纸色底和深毛毡底上看透明边缘。

离线渲染、合成示意图和单张大图不能代替实机截图。v0.72 起项目改用真实运行截图代替合成示意图（v072 ART_SPEC 第 0 节），本流程沿用这一做法。
