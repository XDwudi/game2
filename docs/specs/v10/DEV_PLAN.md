# 骰子构筑 P0 v1.0 开发方案

状态：**执行中**（2026-11-14 起）。依据用户 2026-11-14 的 V1.0 指令（原文见 [规则规格](RULES_SPEC.md) 第 0 节）。指令要求“先写好开发方案，后执行开发”，本文件即开发方案；写完后直接进入开发，不等待逐项确认。
规则的精确定义只写在规则规格里，本文件不重复；验收条件与实际结果写在 [任务](../../tasks/P0-V10.md)。

## 1. 目标

1. 把关卡改成“普通关 → 高压关 → 首领关”的三关周期，首领关带随机减益并在通关后给战利品，让每个周期都有一次需要提前准备的考验。
2. 新增 50 张控制器，覆盖提交顺序、随机生成、骰面长期养成和现有流派的补全；按需补充道具、骰面改造与商店服务。
3. 关卡选择页与商店都能看到本周期三关的目标、减益与战利品。
4. 全部内容接入后，逐卡、逐流派测量强度，重定价格与数值，重新校准关卡目标，并写出整体体验分析。

非目标见规则规格第 11 节。

## 2. 内容总览

| 类别 | 数量 | 说明 |
| --- | --- | --- |
| 新控制器 | 50（C104–C153） | 顺序 6、随机生成 7、骰面养成 12、首领与高压 5、道具与临时骰 4、金币 4、牌型与流派 9、构筑 3 |
| 首领减益 | 39（B01–B39） | 常规 30（一档 8、二档 18、三档 4），终局 9 |
| 战利品 | 6 种 | 稀有控制器、附魔控制器、牌型精研、骰面工坊、特制骰子、道具补给；都可折现 |
| 新道具 | 5（I08–I12） | 破咒符、灵光一闪、蓝色浪潮、点金笔、扩容符 |
| 新骰面改造 | 4（U08–U11） | 精雕、削点、配重、镜像 |
| 新服务 | 3（O09–O11） | 贿赂首领、理财顾问、附魔台 |
| 新插画 | 62 | 50 + 5 + 4 + 3 |

设计上的几条主线：

- **首领减益是“提前知道的考题”**。减益在周期开始时就确定并展示，玩家有两家商店的时间调整构筑；替罪羊、破咒符、贿赂首领是三种不同代价的应对手段。
- **骰面养成给长线回报**。新卡让“把骰子慢慢改造成型”有更多路线：同点（潜移默化）、全 6（拔苗助长）、全 1（大事化小）、全 5（见五成群配千年老二）、2 与 3（二三其德配 2233）、同色（表里同色）、黄金（点金手配金玉满堂）、权重（灌铅）。
- **补上用不起来的流派**。v0.9 的模拟里顺子、留池、玻璃、纹理、少骰这些流派机器人打不出来；本版各补了启动件或回报件（一条龙、顺藤摸瓜、观众席、养精蓄锐、吹玻璃、防碎膜、抛光匠、单刀赴会）。
- **随机生成提供资源流**。百宝袋、杂货郎喂道具流（物尽其用、囤积居奇）；滥竽充数喂祭坛、控制欲、草根逆袭、人员流动；招兵买马补骰子。

## 3. 实施者代为作出的决定

这些是指令没有写明、由实施者选定的做法，都可以在试玩后改：

| 编号 | 决定 | 理由 |
| --- | --- | --- |
| P1 | 高压关仍是可选的，目标从 ×1.25 提到 ×1.5，金币从 +3 提到 +5 | 指令写“可以高压难度，增加分数要求，同时增加奖励”。v0.8 的模拟里机器人后期九成以上都接高压，说明旧数值不构成取舍 |
| P2 | 首领减益在周期一开始就确定并显示 | 指令要求关卡选择时显示一组 3 关并提示减益，给策略空间 |
| P3 | 减益分三档，第一个首领只出一档，三档从第 4 周期才出现 | 指令要求“强弱不一”。前期构筑单薄，强减益会直接判死 |
| P4 | 战利品在首领关后的商店里以“免费报价、可拿 N 件”的形式领取，可以折现成 5 金币 | 领取控制器要栏位，放在商店里可以先卖后拿；不用新增一个流程阶段 |
| P5 | 战利品的种类预先确定并显示，具体候选在通关后才生成 | 指令要求“提示奖励增益” |
| P6 | 终局首领没有战利品 | 通关即结束 |
| P7 | 新增道具 5、骰面改造 4、服务 3 | 指令允许按需增加。破咒符、贿赂首领配合首领系统；精雕、削点、配重、镜像配合骰面养成；其余补道具流与经济 |
| P8 | 首领减益不做插画，用文字加统一的首领标记 | 39 张图的成本高于收益；减益要读的是文字 |
| P9 | 新插画按现行美术标准流程（artgen + 风格套件锚点）制作，先做 1 张代表再成批 | AGENTS.md 第 5 条；v0.9 批次没有走标准流程，是已记录的遗留 |
| P10 | 存档结构升到 6，旧存档按既有流程提示并保留 | 新增周期计划、减益状态、赠礼组等字段 |

## 4. 技术方案

### 4.1 规则核心（`Assets/Game/Core`）

| 模块 | 改动 |
| --- | --- |
| 配置 | `GameConfig` 增加 `bossModifiers`、`lootKinds`、`maxFaceWeight`、`rng.stageSeedXor`、关卡的 `stageKind`、新卡参数；`ConfigJsonContract` 与 `ConfigValidation` 同步；配置由 `tools/v10_config.py` 从冻结的 p0.9.0 配置生成 |
| 计分 | `SubmissionSnapshot` 增加 8 个字段；`ScoreCalculator` 增加新卡、封印、减益系数、骰面变更列表；`ScoreExplanation` 增加对应步骤；`ControllerRules.ResolveSources` 支持失效名单 |
| 会话 | 周期计划的生成与重抽；首领关的入关顺序；预算与容量按减益调整；赠礼组与战利品；新道具、骰面改造、服务；关卡开始 / 结算类新卡；存档校验；调试场景携带新状态 |
| 概率 | 骰面权重进入概率计算（已有 `baseWeight` 字段，此前恒为 1） |

### 4.2 界面（`Assets/Game/UI`）

- 关卡选择页重排为三张关卡牌；同一面板以弹窗形式挂到商店的“查看关卡”按钮。
- 商店增加战利品区与赠礼区（复用现有报价卡与目标选择流程）。
- 对局内的减益标记、封印与失效标记、得分明细新行、结算新行、手册新页。
- 新道具、骰面改造、服务在各处按编号分支的地方逐一补齐（调研已列出全部位置）。
- 所有内容编号必须有插画，否则集成脚本会拒绝；所以插画生成排在最前面启动。

## 6. 验证

- 配置可复现（生成器 `--check`）。
- 旧黄金样例 160 + 260 条在新配置下逐字段不变；新黄金样例由独立参考实现生成，C# 逐字段对拍，每张计分类新卡与每个计分类减益至少各有命中与未命中用例。
- 会话规则用 EditMode 测试覆盖：周期计划、每个会话类减益、入关顺序、战利品与赠礼组、每张关卡开始 / 结算类新卡、新道具 / 改造 / 服务、存档往返、调试场景。
- 模拟器的快速计分与真实计分器对拍 30 万次零差异。
- 全量 EditMode；PlayMode 在 1920×1080 与 1280×720 各一轮。
- Windows 包新目录解压后回放，日志零异常，截图覆盖关卡选择页、商店战利品、首领关。
- 独立复核分别给出规格符合性与制作质量结论。

不能由实施者验证的：真人试玩的手感与难度、macOS 实机、插画的风格验收。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 规则面大（50 张卡 + 39 个减益 + 赠礼组），容易出现交互漏洞 | 规格先行并写清连带规则；独立参考实现对拍；会话测试逐条覆盖；独立复核 |
| 插画数量多，生成额度或时间不够 | 最先启动；串行后台生成并逐张核对参考图；额度不足时如实记录，缺图的内容不混入发行包 |
| 关卡选择页改版会让一批旧的 PlayMode 断言失效 | 逐项改写并记录，不删除测试、不降低阈值 |
| 机器人不会打养成流派，模拟不能代表玩家 | 养成卡用“成型后的状态”单独测量；结论区分“模拟证实”与“推断”；绝对难度留给试玩 |
| 模拟器的命中位图只支持到 C127 | 升级为更宽的位集 |
| 新内容让玩家整体变强，旧目标过易；减益又让首领关变难 | 用整局模拟重新校准全部 24 关目标 |
