已完成Windows可玩原型、Unity工程、可编辑美术源、配置、自动测试和实际运行证据。核心规则以归档原规格为准；不新增玩法和数值。独立最终结论见 `../evidence/review/FINAL_REVIEW.md`，当前汇总状态见 `STATE.md`。真人体验尚未验收。

## 启动与源工程

- 本机直接启动 `Builds/Windows/DiceCraft.exe`，或解压 `Builds/DiceCraft-P0-Windows.zip` 后启动包内exe；必须保留Data目录和DLL。
- 游戏内先体验“练习：锁定与得分”，再开始六关正式挑战。完整操作、存档位置和开发复现见 `../DicePrototype/README.md`。
- 源工程 `DicePrototype/`，Unity 6000.6.7f1；场景 `Assets/Game/Scenes/Bootstrap.unity`，菜单 DiceCraft/Build Windows重建。Blender源与重建脚本见 `../art/README.md`。
- 用户指定仓库：[XDwudi/game2](https://github.com/XDwudi/game2)。最后实际代码版本 `f060098533d26e99e7eba7d0360ecfea78cbe517`；后续交接文档/证据提交不改变游戏代码。

## 性能结果与边界

机器：Windows 10 19045，Ryzen 9 5900X，约64GB内存，RTX 3080 10GB；窗口1080p、D3D11、PC画质。连续180.0146秒，10,750完整帧；真实保存与原规定持续操作保持启用，记录缓冲无扩容。

| 指标 | P95 | 说明 |
|---|---:|---|
| 原LateUpdate帧间隔 | **16.6807ms** | 满足冻结探针≤16.7ms；均值16.7440ms，约59.72帧/秒，最大24.5388ms |
| CPU Main Thread | 16.9783ms | 包含等待，不能当作纯规则计算耗时 |
| FTM帧开始 / Present调用 / 渲染完成 | 16.9825 / 16.9369 / 16.9452ms | 独立诊断时点，100%有效相邻观察；不等同物理屏幕scanout |
| GPU | 0.23552ms | 有效覆盖98.52%，其余明确缺失，没有以零值补齐 |
| UI Canvas.BuildBatch | 0.0066ms | 覆盖100%；此标记不包含全部TMP布局工作 |
| GC分配 | 56,280B/帧 | 中位数0，最大3,519,296B；长历史事务仍有分配尖峰 |

通用Windows60Hz调度按实际释放时刻重锚，前台仅尾段≤1.5ms可能忙等，后台粗睡眠；真实组件销毁/恢复已测，focus/pause回调使用显式注入，未冒充OS切窗。界面刷新提前完成已排队Canvas/TMP工作，降低调度后呈现摆动。历史Player06虽原探针通过但原生时点约18.75ms，未被接受；Player07原生时点同步改善，全部旧数据保留。设计取舍见 `decisions/P0-FRAME-PACING.md`。

以上是指定设备与构建的原型技术结果，不是所有机器恒定60FPS的保证，也没有消除每个慢帧。没有测量物理显示延迟、温升或长期功耗。后续若扩大内容或移动端，需要重新制定并执行相应验收。
