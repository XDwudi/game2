## 2. 设计实现与方案的差异

| 方案条目 | 实际 | 原因 |
| --- | --- | --- |
| 骰库中间的大骰子改走界面图层 | 大骰子仍是桌面相机下的真实骰子（原有开孔方式），列表缩略骰子走界面图层 | 购买改造后的骰面过渡动画直接作用在这颗大骰子上，改图层会牵动已有的改造表现与其测试；它本来就是可拖动的立体骰子 |
| 临时骰在骰池里挂纸签 | 骰池沿用 v0.71 的时钟标记与“临时”文字；纸签只出现在“骰子样式说明” | 骰池时钟标记有逐分辨率的像素校验，纸签会盖住或改变它；本版不动 |
| 托盘上印槽位编号 | 托盘前沿不印号，槽位编号仍在槽内左上 | 编号文字的位置有既有校验；避免同一编号出现两次 |
| 购买控件 | 价签只显示数字，按钮写“购买 / 替换 / 已购买” | 参考图 2 的价签 + 购买两件式 |
| 新增 | 骰库里多了“骰子样式说明”按钮，打开八种样式一览 | 对应参考图 3 上半部分，也用于验收 V73-C；未在方案里单列 |

环境处理（均已记录，未改系统或安全设置）：

- 编辑器的试玩偏好（注册表 `HKCU\Software\Unity\UnityEditor\XDwudi\DiceCraft P0`）里累积了约 7500 条历史测试留下的 `art07.runSeconds.*` 计时记录，另有残留的 `art07.quality`。先导出备份（`artifacts/cache/v073/editor-prefs/UnityEditor-DiceCraftP0-before-purge.reg`，不入库），再只删除这两类测试残留。真实玩家的偏好在另一个注册表项下，没有动。事后测量表明这些记录不是变慢的原因。
- 有一次我误用残留偏好启动了全量运行，主动结束了自己启动的编辑器进程；下次启动时编辑器提示发现场景备份，选择了“Delete”（备份来自被结束的测试运行，场景文件以 git 为准），并删除了该次运行遗留的三个临时测试场景文件。
- 两轮全量运行之间留出几分钟空闲，避免降速阶段落在对实时敏感的测试上。最终三轮运行期间引擎回收耗时稳定在 16–18 ms。

## 6. 仍未处理 / 已知不足

- 骰池里的临时骰没有纸签；托盘前沿不印编号（见 §2）。
- 71 张内容插画没有按参考图重画（没有可用的图像生成工具）；数字没有换成像素字体（方案 D73-1）。
- 高分动画没有专属音效；计分板左栏没有按参考图 4 改成“本次得分 / 计分中”版式。
- 关卡主界面的整体版式没有按参考图 1 重排（不在本版范围）。
- 玻璃骰在深色底上偏实，通透感不如参考图；光滑面的高光带偏硬。
- 首局引导第 5 步的纸条压在“当前持有”条上，条里被盖住的骰子会暂时隐藏。
- `PLAY_ART07_FX_FastSourceMarksLowQualityReplayAndSkipReset` 把自己的准备步骤和结算放在同一帧里计时，正常约 210 ms，上限约 340 ms；机器降速超过 1.6 倍时会失败。这是 v0.72 就有的脆弱点，本版没有改它的判定。
- 构建仍带 Development Build 角标；AudioMixer 总线未接入。
