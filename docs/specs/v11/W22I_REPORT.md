## 0 摘要

- **安装**：`tools/art_v11/install_art.py` 对每个内容 id 与徽记族取“`record.json` 里 `runValid` 为 true 的最新 rNN”，核对记录（版本号、归档路径、job 路径、内容 id）与 `output.sha256` 后逐字节复制。五套各 184 张插画 + 7 张徽记进 `Resources/Themes/<风格>/Art/`（瑞士的 7 张试画被替换），默认风格的 7 张徽记进 `Assets/Art/Art11/Emblems/`。清单在 `tools/art_v11/install_manifests/<风格>.json`。记录缺失或无效时整次拒绝、不写任何文件；第二次运行不写文件。
- **git**：962 个复制件与 ArtSource 原图是同一个 blob（逐个核对），提交 `0337f33b` 新增的 PNG blob 只有 919 张紧凑图标（37.5 MiB）。
- **导入**：962 个 .meta 除 guid、内部 id、精灵名与尺寸外与瑞士试画 `illustration_C08.png.meta` 逐行相同。**发现**：60 张非正方形原图里 49 张按 1024 上限缩放后边长不是 4 的倍数（如 1536×1024 → 1024×683），Unity 保持不压缩（RGBA32，每张 2.67 MiB）；瑞士试画 C08 原来就是这样。没有改导入上限。
- **紧凑图标**：五套各 184 张，六套都绑定到 Bootstrap。32 px 审查发现 **12 张自动裁切失败**（唐三彩 C76、C81、C151、I04、I05、O05；黑金 C64、C151、I05、O05、O08；彩绘玻璃 O05：切掉或切开了骰子、延长块、扳手），都用 `make_crops.py` 的覆写修正，没有生成或编辑图。瑞士、漫画没有。另有与默认相同的 32 px 难读件（W13a 的 C33、C34、C107、C110、C111，细长的 C79、C149、O05、黑金 C19），属画面本身，已列出。

## 3 安装工具与清单（第 1 项）

**规则**（`tools/art_v11/install_art.py`）：

- 对每个内容 id（必须正好是 `P0Config` 的 184 个）与每个徽记族（seal、constraint、multiplier、cards、economy、target、final）取最新的、`record.json` 里 `runValid` 为 true 的 rNN。没有记录的文件夹（被打断、从未记录的运行）与 `runValid` 不是 true 的都不选。
- 选中的记录必须描述自己的文件夹：`revision` 等于文件夹名，`output.archivedPath` 指向这个 `original.png`，`jobPath` 是这个 id 或族的 job，插画的 `content.contentId` 等于 id；`original.png` 的 SHA-256 必须等于 `output.sha256`。任何一项不符、或某个 id / 族没有有效记录、或 id 缺失多出，都整次拒绝（退出码 2），一个文件也不写。
- 复制只在字节不同时写；目标文件夹里计划之外的 `illustration_*` / `emblem_*` 连同 .meta 删除。`--check` 只核对、不写。
- 清单 `tools/art_v11/install_manifests/<风格>.json`（默认 `default.json` 只有徽记）：每个文件的 id 或族、文件名、版本、SHA-256、字节数、像素尺寸、记录路径。放在 `tools/` 而不放在 `Resources/` 下：后者会进构建，并被 `ThemeRegistry` 的 `Resources.LoadAll<TextAsset>("Themes")` 载入。
