# 平衡模拟器（balance_sim）

为平衡性方案提供数据的离线工具（v0.8 起用，现已升级到规则 p1.0.0）。它直接编译游戏的规则核心
（`DicePrototype/Assets/Game/Core/Rules` 与 `Core/Session`），不修改游戏工程里的任何文件，也不被游戏加载。

## 它做什么

| 模式 | 用途 |
| --- | --- |
| `verify` | 把模拟器内部的快速计分模型与游戏真实的 `ScoreCalculator.Evaluate` 逐次对拍，并打印每张控制器、每个首领减益、每种计分效果的覆盖次数 |
| `cards` | 每张控制器在两个参照构筑里的等效倍率（有它 ÷ 没它的期望整关得分）与触发率；成长卡各列两行（成长 0 与标明的中期成长值）；改骰面的卡另列“正常打 6 关 / 12 关之后”两行 |
| `scen` | 手工搭好的场景：骰面养成的终态、乘区四件套、裸装过关概率，以及 v1.0 各新流派的成型状态 |
| `run` | 机器人通过真实的 `GameSession` 用合法命令打完整局，输出逐关到达率、通过率、金币收支、购买统计、死亡分布，以及 v1.0 的关卡类型、首领减益、战利品、高压挑战统计 |
| `trace` | 把机器人某一局开头的若干条命令录成 JSON（`--seed`、`--steps`、`--out`），供打包后的游戏用 `--art073-capture … --art073-trace …` 回放并截图 |

## 运行

需要 .NET SDK 10。从仓库根目录执行（`--threads` 限制并行度，默认最多 8）：

```powershell
dotnet build tools/balance_sim/BalanceSim.csproj -c Release
$sim = "tools/balance_sim/bin/Release/net10.0/BalanceSim.dll"
dotnet $sim verify --n 300000 --out evidence/v10/balance/verify_p100.json --log evidence/v10/balance/verify_p100.log
dotnet $sim cards --hands 3000 --threads 8 --out evidence/v10/balance/cards_p100.json --log evidence/v10/balance/cards_p100.log
dotnet $sim scen --hands 2000 --threads 8 --out evidence/v10/balance/scen_p100.json --log evidence/v10/balance/scen_p100.log
dotnet $sim run --first 5000 --seeds 300 --threads 8 --out evidence/v10/balance/run_p100_current.json --log evidence/v10/balance/run_p100_current.log
```

- 所有模式都接受 `--config <路径>`（模拟候选数值）和 `--log <文件>`（把屏幕输出同时写成 UTF-8 文件）。
  不要用 PowerShell 的 `>` 重定向来存日志（中文会变成乱码），也不要接 `Select-Object -First N`（进程会在写出 JSON 之前被杀掉）。
- 一次 300 局的 `run` 在 8 线程下约 20–40 分钟；结果与线程数无关（每个种子自成一局）。
- 结果里的 `NaN`（例如空集合的中位数）在 JSON 里写成 `null`。

### 关卡目标候选与校准

```powershell
# 24 个数 = 第 1..24 关的普通目标；高压关的 riskTarget 自动 = 普通目标 × 1.5
python tools/balance_sim/make_targets.py --name v10_t1 --targets 300,600,...
# 只改后段：--from 12 加 13 个数
python tools/balance_sim/make_targets.py --name v10_t1 --from 12 --targets 46000,...
dotnet $sim run --config tools/balance_sim/candidates/v10_t1.json --first 5000 --seeds 300 --threads 8 --out evidence/v10/balance/run_v10_t1.json --log evidence/v10/balance/run_v10_t1.log
python tools/balance_sim/calibrate.py summary evidence/v10/balance/run_p100_current.json evidence/v10/balance/run_v10_t1.json
python tools/balance_sim/calibrate.py predict --fit evidence/v10/balance/run_p100_current.json --base evidence/v10/balance/run_p100_current.json --targets 300,600,...
python tools/balance_sim/calibrate.py solve   --fit evidence/v10/balance/run_p100_current.json --base evidence/v10/balance/run_p100_current.json --win 0.25 --boss-gap 0.03 --round
```

- `make_targets.py` 只改 `normalTarget` 与高压关的 `riskTarget`（× 3/2），其余原样复制，写到 `tools/balance_sim/candidates/`。
  目标必须是偶数（× 1.5 与首领减益的 × 150% / × 200% 才是整数）；模拟器自己的宽松校验也检查这一点。
- `calibrate.py summary` 汇总若干次 `run`：通关率、每四关一段的死亡占比、逐关与分关卡类型的通过率、高压接受率、最后一关（终局减益生效前）的实力 ÷ 目标。
- `calibrate.py predict / solve` 是挑候选时用的纸面估算，**只用于选候选，不是证据**，每个候选都要真跑：
  用已有模拟拟合“实力 ÷ 目标 → 通过率”（全部 24 关），再把每个种子按新目标重走一遍。高压关按机器人自己的规则重新决定接不接
  （保守实力 ≥ 1.3 × 1.5 × 目标）；首领关沿用该种子记录下来的“带减益 ÷ 不带减益”比例。它不知道目标变了以后机器人会怎样改变购物。
  `solve` 按目标反推：给定通关率，让六个四关段的死亡数相等、首领关比同段其他关难 `--boss-gap`、任何一关不低于 `--min-clear`。
- `make_candidate.py`、`fill_plan.py` 与 `report_tables.py` 是 v0.8 方案用的旧脚本，输入是 `baseline/` 里冻结的旧配置。

## 快速计分模型与对拍（`Fast.cs`）

`Build.Score` 用 double 复刻 `ScoreCalculator.Evaluate`。p1.0.0 覆盖：

- 全部 150 张控制器：留池骰、本手已投次数、剩余投掷、本关剩余提交、永久骰数量、逐骰事实（纹理、整骰同色、整骰同点、对面点数、临时骰）、
  再计、牌型倍率加值、场外红人与锦上添红的红组数量、成长值、百变模仿与被复制卡共用成长值、昙花一现的衰减、
  一掷千金按冻结钱包从左到右占用预算（只有前 ⌊钱包 ÷ 3⌋ 个来源触发，附魔也只算这些来源的）。
- 首领减益的全部计分效果（`ModFx`）：八种封印、禁顺、小打小闹、不重样、半吊子、打回原形、褪红、褪蓝、慢热、强弩之末、釜底抽薪、成长归零、附魔沉默。
- 本关失效的控制器（不是来源，但仍计入控制欲、草根逆袭的件数与留白的占用栏位）、蓝色浪潮、灵光一闪、关卡类型、背包道具数、普通栏位数、本关已用过的主牌型。
- 命中集合 `HitSet` 是 192 位（p0.9.0 的 `UInt128` 只到 C127）。

`verify` 的判定：快速值与真实计分的**精确有理数**（`scoreNumerator / scoreDenominator`）相对误差 ≤ 1e-9，向下取整后的分数一致，
主牌型一致，并且**触发的控制器集合**与真实计分完全一致。随机样本：0–9 张随机控制器加附魔（四分之一的样本在随机位置放一张百变模仿，
成长卡带 0–200 的成长值，昙花一现 0–3）；1–10 颗骰子，随机点数 / 颜色 / 纹理 / 黄金 / 玻璃 / 骰面权重 / 临时骰，含整骰同色与整骰同点；
留池骰 0–5 颗；已投 1–6 次；剩余提交 1–4；永久骰数量 0–8；钱包 0–129；提交栏容量一半取自控制器、一半随机 1–8；
五分之三的样本带一个随机首领减益（39 个等概率）及它造成的失效控制器，另有六分之一的样本再随机失效一两张；
随机的关卡类型、背包道具数、普通栏位数、本关已用牌型、红 / 蓝浪潮、灵光一闪；
三分之二的样本把朝上的面往某种形状凑（同点、对子、三条、顺子、回文、全偶数、+1 递增、恰好一对；颜色交替、红在左、单色），保证牌型类与顺序类卡片有足够触发次数。

输出末尾三张覆盖表，任何一项为 0 则判失败：每张控制器“出现 / 触发”；每个首领减益“出现 / 去掉它之后精确分数不同”；
每种计分效果“出现 / 真的起了作用”（例如禁顺要求去掉减益后确实有顺子）。另有“失效控制器改变了结果”的计数。

## 机器人怎么玩

- 对局：每次投掷后，对“锁哪些骰、是否提交”做抽样前瞻（最多看两次投掷），目标是尽快凑够本关剩余分数。
  它只看当前可见的骰面，不读取任何随机数状态；规划用自己独立的随机流。
  前瞻里每一次估分都带着真实的提交上下文：这次提交后**留在池里的骰子**、**已投次数**、**剩余投掷**、**本关剩余提交次数**，
  以及 p1.0.0 的**首领减益、失效控制器、本关第几次提交、本关已用牌型、背包、空栏位**。
  `run` 会统计“规划器对自己选定的提交给出的分数”与真实会话结算的分数是否一致（不含错乱乘积），输出在 `planner self-check` 一行；首领关同样计入。
- 商店：对每件商品，用同一批模拟手牌估算“买了之后的关卡得分 ÷ 现在的关卡得分”，按每金币收益排序购买。
  估值同时看平均手和较差的一手（第 25 百分位），所以高方差的卡不会按好运气估价。
  下一关看起来危险时不留钱，安全时为利息留钱；超过利息上限的余钱只要有提升就会花掉。
  买了之后剩下的钱会低于留钱线的商品不做估值（购买规则本来就不会买它，省掉估算时间）。
  估值用的模拟手牌按本关的提交位置轮转（第 1 / 2 / 3 次提交），所以渐入佳境、开门红、移花接木、慢热 / 强弩之末这类“看第几次提交”的效果按整关平均计入。
- 栏位：用本局的 `controllerSlots`（开局 5）。普通栏位用满、至少还剩 3 关时，把“扩充栏位 O08”当作每金币 0.10 收益的商品。
- 栏位已满时换卡：只尝试卖掉“拿掉后损失最小”的两张。p1.0.0 起，总件数到 10 件上限时也按同样的办法换卡（此时不占栏位的卡也可以被换掉）。
  百变模仿的位置：自己持有的构筑和货架上的百变模仿仍然全位置搜索；估其它商品时只试“当前位置”和“紧贴新卡左侧”。

### p1.0.0：关卡周期

- **关卡选择**：读取会话给出的周期面板（`CycleView`）与入关预告（`EntryView`、`EffectiveCapacity`、`InitialRolls`、`InitialSubmissions`）。
  首领关用“带减益、带失效控制器、按预告的预算”估一次实力，再用“没有减益”估一次，两者都记进日志。
  机器人自己用 `ControllerRules + StageRules` 算出的预算若与会话预告不一致，会计数并在 `run` 里报告（应为 0）。
- **高压挑战**：保守实力（每手都按第 25 百分位）≥ 1.3 × 高压目标（= 1.5 × 普通目标）时才接。`run` 报告接受率、接受后的通过率、逐关接受率。
- **首领关对局**：规划器的计分模型带着减益（封印、禁顺、小打小闹、不重样、半吊子、等级归零、褪色、减半、只计点数、成长归零、附魔沉默、失效控制器）；
  预算类减益（投掷、提交、容量、目标）直接读会话里的实际数值。`MustFill`（满员）：只考虑恰好 min(容量, 存活骰子) 颗的提交。`NoItems`（徒手）：只用破咒符。
- **提交顺序**：对“桌面上真实的这一手”，4 颗以内穷举全部顺序；5 颗以上用构造法各试一个候选——按价值把骰子分配到“再计 / 封印”栏位
  （一马当先、压轴好戏、中流砥柱；出头鸟封第 1 位、隔行封印封第 1/3/5/7 位：价值最低的骰子放进被封的位置）、每颗骰子轮流当第一颗（首当其冲、大数开路、排头兵）、
  不断增加的等差三连、红蓝相间（交替排）、泾渭分明（红在左）、对称美学（成对镜像）、顺藤摸瓜（切成若干 +1 递增链）——真正提交前再用两两交换做一次爬山。
  得分相同的顺序里，再按养成偏好挑一个（潜移默化：第一颗放点数大且同点面最多的；点金手：最后一颗放还没镀金的大点；移花接木：好面在前、差面在后）。
  **前瞻里抽样出来的未来手牌**只用构造法（不穷举，第一颗只试点数最大、贡献最大、以及首当其冲时最大的红 / 蓝骰）：穷举会让带顺序卡的构筑慢一个数量级。
  只有再计 / 封印栏位效应的构筑（没有上述“图案”卡）始终是精确分配。

| I12 扩容符 | 首掷前：存活骰子多于容量、多一格能让估算实力提高 ≥ 10%、且保守实力 < 2 × 目标 |

| I11 点金笔 | 提交前：给顺序里第一颗骰子镀金（顺序无所谓时先把点数最大的未镀金骰子换到第一位） |
| I09 灵光一闪 | 提交前，这一手本身不够过关，并且：翻倍后够过关，或是本关最后一次提交，或本关偏险（保守实力 < 1.3 × 目标）而这一手不低于平常一手的 70% |
| I03 / I04 / I05 | 不使用 |

商店里：下一关保守实力 < 目标时按顺序买 I06、I09、I07、I02、I12（应急，沿用旧逻辑并加入新道具；下一关是“徒手”首领时不买）。
首领对策每家店至多一次：下一关就是首领、减益让实力下降 ≥ 25% 且保守实力 < 1.5 × 目标时买货架上的 I08；否则见“贿赂首领”。

### p1.0.0：赠礼组（首领战利品、杂货郎、铁匠铺）

赠礼组里的每个报价与货架商品用同一套估值（成长投影后的实力对数增益 + 经济加成），价格为 0，先于付费购买处理。

- 控制器：栏位满时与购买一样，按“卖掉最不重要的两张之一”估值并先卖后领。
- 牌型精研：按 +2 级（不超过上限）估值。特制骰子：与新骰相同。骰面改造：见下表的目标面。
- 道具：按“这个道具对机器人值多少金币” × 0.04：I06 3、I09 3、I07 2.5、I11 2.5、I02 2（骰子未满时）、I12 2（永久骰多于容量时，否则 0.5）、
  I08 4（即将面对的减益让实力下降 ≥ 25% 时，否则 1）、I10 / I01 1、I03 / I04 / I05 0。
- 折现：+5 金币折成 5 × 0.04 = 0.20（下一关危险时 5 × 0.012 = 0.06，此时金币不如实力要紧）。可拿的几件加起来不如折现、或没有一件有用时拿金币。
- 杂货郎 / 铁匠铺的三选一没有折现：拿增益最高且为正的那一件。

### p1.0.0：骰面改造与服务

| 商品 | 机器人的做法 |
| --- | --- |
| U03 / U04 / U06 | 沿用：最早的一颗有合法面的骰子，逐面试 |
| U08 精雕 / U09 削点 | 最早的一颗有合法面的骰子：点数最低的面和最高的面各试一次，取实测增益高的 |
| U10 配重 | 同一颗骰子：最值钱的面（点数 × 黄金）和这颗骰子最常见点数的面 |
| U11 镜像 | 同一颗骰子：对面不同的面里点数最高的和最低的 |
| U05 脆化 | 沿用：估值打五折（有防碎膜时打九折） |
| U01 / U02 / U07 | 不购买 |
| O09 贿赂首领 | 减益让实力下降 ≥ 30% 且下一关就是首领且保守实力 < 1.5 × 目标；或下降 ≥ 50%（首领还隔一两关也买）。每家店至多一次，不看利息储备 |
| O10 理财顾问 | 按利滚利的算法估值：每关多 2 金币利息 × 0.04 × min(10, 剩余关数) × 0.6；钱包没到新上限时按差额折算，宽裕时按全额 |
| O11 附魔台 | 固定估值 0.14（各附魔的权重 × 效果），栏位已满时 +0.11（抽到不占栏位）；至少持有 3 件控制器才买 |
| O05 / O08 | 沿用 |

单个骰面的改造对实力的影响通常只有百分之一二，低于机器人的噪声门槛（0.06），所以它只在某张卡让这个面变得要紧时才付钱买；免费的赠礼则只要增益为正就拿。

### 成长卡怎么估值

成长卡买来时成长值是 0。商店估值时，对构筑里的每张成长卡（已有的和候选的一视同仁）先把成长值推到

> growth′ = min(上限, 当前成长 + 每关成长率 × 视野)，视野 = min(剩余关数, 6)；下一关看起来危险时取 2

再算实力。上限：乘法卡 100（×6），加法卡 300。每关成长率用机器人看得到的量估（S = 最近各关平均用掉的提交次数）：

| 卡 | 每关成长率 |
| --- | --- |
| C55 积少成多 | 2 × S |
| C56 深蓝 | 2 × S × 模拟手牌里“没有红面”的提交占比 |
| C57 红火 | 3 × S × 模拟手牌里“红组 ≥ 3”的提交占比 |
| C58 老当益壮 | 4 |
| C59 余勇可贾 | 4 × 最近各关平均剩余的提交次数 |
| C60 千锤百炼 | 2 × 最近各店平均到手的骰面改造次数（购买与赠礼） |
| C61 学无止境 | 2 × 最近各店平均购买的牌型 / 颜色等级数 |
| C62 熟能生巧 | 1 × 模拟手牌的平均投掷次数 × S |
| C90 玻璃心 | 15 × 玻璃骰数量 × 碎裂概率 × 平均投掷次数 × S ÷ 2 |
| C54 连庄 | 3 × S × p（p = 相邻两手主牌型相同的概率），且不超过稳态值 3p ÷ (1 − p) |
| C100 祭坛 | 0（机器人不喂它） |
| C129 屠龙者 | 10 × 视野内的首领关数（终局首领不算） |
| C132 高压锅 | 12 × 视野内的高压关数 × 机器人自己到目前为止的高压接受率 |
| C134 物尽其用 | 3 × 最近各关平均使用的道具数 |
| C141 昙花一现 | 反向：按视野内倍率的几何平均估值（消失之后按 ×1），平均低于 ×1.25 时当作没有这张卡 |

“最近各关”的量与一个相当于三关的先验值混合，避免开局几关的偶然值。判断“下一关危不危险”仍用当前真实成长值。

### 骰面养成卡怎么估值（p1.0.0）

持有（或正在考虑）这些卡时，先把骰子改成“视野之后大概会变成的样子”，再估实力。N = 视野 × S，D = 每次提交的骰子数，都取自机器人自己的模拟手牌。

| 卡 | 投影 |
| --- | --- |
| C120 拔苗助长 / C121 大事化小 | 精确：每关每颗永久骰最小面 +1 / 最大面 −1 |
| C117 点金手 | 0.8 N 个面镀金，各骰轮流、先镀点数大的 |
| C118 表里同色 | 提交骰里某种颜色 ≥ 60% 时：颜色不同的对面成对染成该色，至多 0.5 N D 对；否则不投影 |
| C119 潜移默化 | 0.5 N 个面变成该骰的最大点（小点数构筑取最小点），一颗一颗来 |
| C122 见五成群 | 0.8 N D 步，每步把离 5 最远的面向 5 挪 1 点，各骰轮流 |
| C123 二三其德 | 0.8 N D 步，每步把 2–3 之外最远的面向里挪 1 点 |
| C124 灌铅 | 0.8 N D 步，每步给该骰最值钱的面权重 +1（到上限为止） |
| C125 抛光匠 | 1.6 N 个无纹理的面变光滑，先大点 |
| C126 养精蓄锐 | 0.8 N × 每次提交的留池骰数 步，每步给最小的面 +1 |
| C127 移花接木 | 0.7 × 视野 次，把全场最好的面复制到另一颗骰子最差的面上 |

这是近似：真实的变化取决于每一手掷出什么。`cards` 里的 `@s6 / @s12` 行是用规划器实际打 6 / 12 关、按真实计分器给出的骰面变更一步步改骰子得到的，可以对照。

### 经济卡与生成卡怎么估值

不计分的卡按“等价金币”折成收益：1 金币 = 0.04（机器人平时的每金币购买门槛）× 还能生效的关数（封顶）× 折扣。B = 之后还有商店的首领关数，R = 剩余关数。

| 卡 | 估值 |
| --- | --- |
| C01 存钱罐 / C52 成长基金 / C43 牌型提升 | 沿用 v0.8 |
| C95 铁饭碗 | 每关 3 金币 |
| C96 利滚利 | 每关 (钱包 − 计息上限) ÷ 5，0–5；机器人处于“宽裕”状态时至少按 2.5 计。持有后它的留钱上限同步提高 |
| C97 以战养战 | 每关 3 × min(2, S × 模拟手牌里单手 ≥ 下一关目标一半的占比) |
| C98 砍价高手 | 每关 1 × 最近各店平均购买的控制器与骰面改造件数 |
| C99 聚宝盆 | 最近各店平均卖出的控制器件数 × 剩余关数 × min(剩余关数, 6) ÷ 2（整段剩余流程的合计） |
| C110 百宝袋 | 每关 1.4 金币（随机一个道具对机器人的平均价值） |
| C111 杂货郎 | 每家店 2.5 金币（三选一里最好的道具） |
| C112 滥竽充数 | 每个它还能填上的空栏位 2 金币 |
| C113 铁匠铺 | 每家店 1.5 金币 |
| C114 点化 | 每个首领 0.15（一个随机附魔的估值）× 0.6 |
| C115 无心插柳 | 每剩一关 0.004 |
| C116 招兵买马 | 每个首领 4 金币，以永久骰的剩余空位为限 |
| C133 赏金猎人 | 每个首领 5 金币 + 每个高压关 3 金币 × 接受率 |
| C140 回收大王 | 每卖一张控制器 2 金币 |
| C145 防碎膜 | 每颗玻璃骰 0.10（持有吹玻璃再加 2 颗），封顶 0.6 |
| C131 替罪羊 | ln(不带减益的实力 ÷ 带着即将面对的减益的实力) 的一半 |

## 已知局限（解读数据时必须考虑）

1. 机器人不会经营“养成型”控制器。v0.6 的 C07、C15、C26、C36、C37、C38、C43 它只按当下收益估值；p1.0.0 的骰面养成卡按上面的投影估值，
   但它在对局里只做一件事来配合：得分相同时挑一个更利于养成的提交顺序。它不会为了养成多提交、换打法或专门留骰。成型后的强度在 `scen` 里单独测量。
2. 机器人不使用：光滑 / 粗糙 / 随机变形骰面，遥控骰子、大数多来、小数多来，以及道具槽、折扣、免费刷新、增加道具、删除骰子等服务。
   达标后它立刻结束本关，不会为了成长或养成而多提交。
3. 机器人胜率不是玩家胜率。它适合比较两套数值的相对差异和曲线形状，不能直接当作“玩家有百分之多少能通关”。
4. p0.9.0 起的盲区：
   - **C100 祭坛永远不买**（若因故持有，会把它排到最右，不摧毁任何卡）。它的强度只在 `cards` 里按假定成长值列出。
   - 成长卡只在商店估值时被“预支”成长；对局里的手牌策略不会为了成长去改打法
     （不会为深蓝刻意交全蓝、为红火凑红组、为熟能生巧多投、为连庄维持同一主牌型、为余勇可贾省提交）。
   - 依赖它不会做的操作的卡被低估或永远不触发：C91 纹理大师（不买光滑 / 粗糙面）、C103 精兵简政（不删骰子）、
     C92 纯色主义与 C93 始终如一（不会刻意把一颗骰子做成同色 / 同点）、C90 玻璃心（很少买玻璃骰）、C60 千锤百炼（买骰面改造少）。
   - 前瞻最多看两次投掷：有“再给一次”、投掷附魔或“再来三次”而剩余投掷 ≥ 3 时，对“孤注一掷 / 越挫越勇”只是近似。
   - 栏位已满时只试两张“最不重要”的卡作为被换下的对象。
   - 实力估计里“只在某一次提交生效”的卡（C68、C102、C153、C127、C150 的后几手）计入平均实力，但基本不进入“较差一手”的估计。
5. p1.0.0 新增的盲区：
   - **首领减益只影响当关的打法，不影响长期构筑**。机器人不会因为“本周期的首领封红”而提前避开红色构筑；它只在下一关就是首领且看起来过不去时，
     才按带减益的实力给商品估值，其余时候用贿赂首领 / 破咒符 / 替罪羊这三样对策。
   - **会话类减益里的长期代价没有进入打法**：削级（每次提交主牌型永久 −1 级）、苛税（每颗提交骰 1 金币）、停滞、白干、过路费。
     机器人不会为了少降级 / 少交税而少提交或换牌型，只有削级会触发破咒符。
   - **提交顺序是近似搜索**：5 颗以上不是穷举，构造法 + 爬山可能漏掉多张顺序卡叠加时的最优排法；前瞻阶段（决定锁哪些骰）用的是不带爬山的估值，对顺序卡略偏保守。
   - **高压挑战只看实力余量**，不看金币需求、高压锅 / 赏金猎人的收益，也不为屠龙者、高压锅刻意保留构筑。
   - **道具**：I09 不会留给最强的一手，只按上面的条件用；机器人不为囤积居奇刻意留道具；
     不买道具槽，所以百宝袋 / 杂货郎的道具常因背包满而拿不到（它会用掉一个腾位置）。
   - **金币类卡**：一掷千金、富甲一方、有钱真好按“估值那一刻的钱包”计入，机器人不会为它们调整花钱节奏。
   - **吹玻璃 / 玻璃流**：只有“下一颗变玻璃”的即时收益和一个固定折扣，没有模拟骰子逐关碎掉的过程。
   - **滥竽充数、点化、无心插柳、附魔台**的随机结果只有固定估值；机器人不会因为栏位空着就多买滥竽充数。
   - 单面的骰面改造（U08–U11）低于噪声门槛，很少被购买；多次购买才成型的骰面路线它走不出来。
   - `cards` 的 `@s6 / @s12` 行不模拟金币、成长值、玻璃碎裂与随机的关末效果；每关固定打满 3 手（真实对局里机器人平均只用 2 手左右，养成更慢）。
6. `ConfigValidationRelaxed.cs` 取代了游戏里钉死数值的 `Validate()`，只在模拟器里生效；p1.0.0 起它也提供 `Modifier`、`Loot`、`ModifierEffects`，
   并检查周期结构、首领池、战利品种类与目标的整除性。
