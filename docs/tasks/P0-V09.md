# P0-V09：50 张新控制器与配套机制（p0.9.0）

状态：**REVIEW**（2026-11-14 实施与自动验证完成；等待用户试玩。实施者不签署 ACCEPTED）

## 1. 目标与输入

- 目标：按 [规则规格](../specs/v09/RULES_SPEC.md) 实现 50 张新控制器（C54–C103）、成长值 / 再计一次 / 留池骰 / 投掷阶段 / 牌型倍率加值五个机制、普通栏位 5–7、货架 4、服务 O08，并上调后段目标；发出可试玩的 Windows 与 macOS 包。
- 输入版本：p0.8.0（分支 `codex/v0.8`，提交 `f0201d6`）；规格 `docs/specs/v09/RULES_SPEC.md`；用户 2026-11-14 的答复（规格第 0 节原文）。
- 非目标：无尽模式、高压关三选一、商店流派偏向、新道具与新骰面改造、移动端。
- 工具：Unity 6000.6.7f1、.NET SDK 10（规则宿主与模拟器）、Python 3（配置与参考实现）、本机 Codex CLI 的内置图像生成（卡面）。

## 4. 准备度检查（开工前）

- 规格：50 张卡逐张有触发条件与数值；连带规则（模仿、预算下限、祭坛时点、砍价顺序）在规格 4.9 节。

- 高风险未知项先做了最小试验：
  1. 图像生成——用 C54 做样张（100 秒 / 张，1254² 透明底，与既有 C33 并排风格一致）后才启动批量。

  3. 规则宿主——改动后先在 .NET 宿主编译并跑旧会话测试（275 / 287，12 项为钉值，见 §5）。
- 验证环境：与 v0.8 相同（本机 Windows，Unity 批处理 + 带窗口编辑器）。

## 9. 仍未处理 / 已知不足

- **没有真人试玩。** 新卡好不好玩、看不看得懂、成长节奏是否合适，都没有人的判断。
- **平衡只验证到“机器人层面”。** 后段目标只跑了一个候选；机器人不会为成长卡、牌型专精卡、骰面协同卡改变打法，也从不买祭坛，所以这些卡的真实强度没有数据。便宜的成长加分卡测出来偏强（`evidence/v09/balance/README.md`），没有改。
- **卡面插画**只有实施者目检，没有美术复核，没有逐张在 64 px 下验收，也没有按新的标准流程（风格套件锚点）生成；与标准流程的差异见 `ArtSource/Art09/README.md`。
- **新机制没有专属演出与音效。** 再计一次、成长、祭坛摧毁都沿用通用的计分节拍和文字提示；留池骰只有一行文字汇总，骰子本身没有标记。
- 商店里拖动百变模仿可以先后复制两张被动卡（复核 F3），保留待定。
- 祭坛只有事前提示，没有“开始挑战”时的二次确认。
- 配置校验没有钉住新卡的规格数值（复核 F9）。
- 没有 macOS 实机启动；Windows 帧时间与独占全屏专项未重测（v0.7 起未通过）；游戏内置的回放校验（`PlayerVerification`）录制于 p0.6.0，没有重录也没有运行。
- 文字缩放 125% / 150% 时，两项服务仍是滚动列表而不是两张并排的小卡。
- 构建仍带 Development Build 角标；AudioMixer 总线未接入。
