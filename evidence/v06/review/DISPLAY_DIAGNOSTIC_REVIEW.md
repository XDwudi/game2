## Hypotheses and discriminating observations

The production native apply currently reads back after two yielded frames. A premature rollback remains a hypothesis until native frames show a still-progressing transition. The native failure message alone does not give an HRESULT or identify a cause.

1. Compare each exact requested dimension/refresh tuple with the recorded `Screen.resolutions` tuple. An unsupported tuple establishes a selection defect; a supported tuple excludes that particular defect but not a driver or OS rejection.
2. Observe the explicitly visible launch and its actual focus state on each frame. Compare with the prior hidden/occluded launch hypothesis. Do not manufacture focus through unapproved external input or infer focus solely from successful synthetic keyboard handling.
3. Check whether the requested mode was ever read back, whether a mismatched frame precedes production rollback, and whether the native engine reports rejection before that rollback. If the failure persists while visible, focused and requesting an enumerated tuple, a longer wait by itself has not explained it.

Unity 6000.6 documents that exclusive D3D11 mode automatically uses BitBlt even when the flip option is enabled, and recommends keeping flip enabled for windowed performance. [Unity useFlipModelSwapchain](https://docs.unity.com/en-us/engine/6000.6/script-reference/unityeditor/playersettings/useflipmodelswapchain)

Unity documents applying resolution at the end of the current frame, and selecting the highest available refresh when the requested refresh is unsupported. This does not guarantee a mode transition has settled in two frames on every host. [Unity SetResolution](https://docs.unity.com/en-us/engine/6000.6/script-reference/unityengine/screen/setresolution)

Microsoft lists an occluded window, missing keyboard focus and another fullscreen application among potential causes of `DXGI_ERROR_NOT_CURRENTLY_AVAILABLE`, and defines a separate transition-in-progress status. These are candidate causes, not a diagnosis of this run without the corresponding native error or observed condition. [Microsoft SetFullscreenState](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/nf-dxgi-idxgiswapchain-setfullscreenstate)

Conclusion at this point: diagnostic source review passed; native exclusive display remains failed/unresolved; whole Windows Player acceptance and macOS real-device acceptance are not claimed.
