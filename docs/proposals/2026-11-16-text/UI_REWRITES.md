## 1. 摘要

**问题计数（按表格行计，一行可含多个代码）**：J 行话 166 · D 开发信息/编号 61 · A 歧义 30 · L 截断/溢出 13 · C 不一致 71 · N 数字格式 16 · G 语病 7 · X 信息架构 37（共 310 行有问题的表格行）。

**对新玩家危害最大的 10 处**
1. 计分处到处是分数和科学计数：横幅 “倍率 ×702/5”、公式条 “111 × 8 × 4.5 × 39/10”（同一行小数和分数混用、没有标签）、明细里 “38961/10”、超长时 “≈1.23e15”。玩家读不出倍率是多少。
2. “结束本轮”其实是“结束本关并结算”，未达标时按钮灰着也不说明原因；悬停说明里又叫“余次奖励”，左栏叫“剩次奖励”，结算页叫“剩余提交奖励”。
3. 关卡结算页用会计用语：“本次现金净增”“奖励前余额 0 → 结算后余额 7”“提交收入（本关已入账）…不再次加入现金净增”“本关奖励已处理”；“利息 +0”没有任何计算说明。
4. 两步锁定的词混乱：按钮“清除待选”、骰子下方“01 待锁”、引导“待选”、按钮“确认锁定 0”；“已锁定 · 本手不可移回骰池”一直挂在屏幕上（没锁也显示）；默认提示“锁定不可撤销 · 提交将消耗 1 次提交”是规则陈述，不告诉玩家下一步做什么。
5. 内部编号外露：“容量 K 5”“续交 C01 +0 / 次”（没有存钱罐也显示）、“首次提示 · C53 的倍率…”、骰库 “D001”“物理对面 F01/F06”、控制器详情卡上 “ITEM_00012”、购买回执 “已装备 X · ITEM_00012 · 技能详情 · 无附魔”、得分明细 “[ITEM_00003 → ITEM_00005]”、“飘忽不定：下一颜色 ITEM_00003:red”。
6. 商店卡面用占位词代替效果：控制器卡底部“技能详情”“查看条件”；道具/服务/改造卡的效果被“…”截断（服务卡 100×52 px 只放得下约 20 字）。
7. 练习模式（手册里的“独立固定骰练习”）整套显示调试标签：左栏副标题“调试对局”、商店“调试配置 · 持有”、结果“调试时长未记录”；设置页常驻“调试口令”输入框。
8. 得分横幅：“连锁 N”无解释（实际是本手生效的控制器张数；得分横幅上为 0 也显示，稳定结果栏与计分阶段说明在 0 时已隐藏）；“超高分”实际含义是“一手达到本关目标”（312 对 300 即触发），“高分”=达到一半、“爆分”=两倍。
9. 快捷键提示写死：“掷骰 3 [R]”“牌型手册 [H]”改键后仍显示旧键；确认锁定/提交/清除三个按钮没有任何快捷键提示；“演出速度”选项是英文 Instant/Fast/Normal。
10. 同一概念多名：章/周期、道具/局内道具/消耗品、升级/研究强化/研习/强化、栏位/普通槽/占槽/免槽、过关奖励/基础奖励、掷骰/投掷/重掷、挑战（整局）/挑战（普通、高压）。

**另外两处容易误导的状态**：新关开始时分数栏仍显示上一关最后一手“上一手得分 · 已保存 600”（截图 42）；计分动画期间底部提示仍显示动画前的状态（截图 13 “没有未锁骰；可提交已锁骰”）。

**反复出现的模式**：① 字符串直接拼接规则引擎原始值（分数字符串、实例 ID、英文枚举、异常 Message）；② 用系统状态句代替行动指引；③ 规格/会计词（有效、合法、实例、计息本金、净增、入账、冻结、回执、快照、只读、检查点）；④ 固定小框 + Ellipsis 截断效果文；⑤ 版本迭代留下的新旧说法并存（v0.7 的“研习/普通槽”与 v1.0 的“章/栏位”）。

## 3. 格式规则建议

### 3.1 倍率与分数：分数 → 小数

规则（遵循术语表 §3）：倍率一律小数，最多 2 位，去尾 0（702/5 → 140.4，39/10 → 3.9，9/2 → 4.5）；除不尽的循环小数显示“≈”（1/3 → ≈0.33）。只改**显示**；“复制公式”可继续复制精确分数以便报错。

需要改的函数（都只做字符串格式化）：
- `GameApp.Art07.cs` `ScoreFactorShort07`（L475-489）：现返回 “702/5” 或 “≈1.23e15”。改为：分子÷分母取 2 位小数并去尾 0；超过 12 位整数时按 §3.3 大数规则。它被分数栏因子（Art07.cs:451,452）、横幅（Art073HighScore.cs:75,79）共用。
- `GameApp.Art07Effects.cs` `DisplayFraction07`（L269-273）：现只处理 “/2”。泛化为任意分母。它被浮标、稳定结果栏、随机揭示共用。
- `GameApp.Art07Presentation.cs` L251（“总倍率”拼接）与 `EventText07` L214-216（`name+operation+value` 未转换）。
- `GameApp.Art07StableResult.cs` L51。
- `GameApp.Art073HighScore.cs` L77、L79，以及 `Runtime/Presentation/HighScore073.cs` `Formula`（L48-58）：同时加标签（基础/牌型/颜色/红组/控制器/附魔），并把 “2^n” 改为附魔实际倍数 “×4”。
- `GameApp.Art07ScoreDrawer.cs` `ScoreFormula07`（L77）、`ScoreStepCalculation07`（L78）；`GameApp.Modals.cs` `ScoreStepText`（L351-355）、`ShowBreakdownComplete07` L310：步骤中间值（如 “38961/10”）显示为小数；省略 ×1 的项；“2^0” 省略。

## 4. 术语冲突与待决

**术语表未覆盖或与界面需要冲突的地方**
1. **掷骰 / 投掷 / 重掷**：术语表未规定。界面按钮“掷骰/重掷”，左栏“投掷”，引导“投掷”，拒绝提示“投掷次数”“空投”“首掷”“剩掷”。建议：动作=掷骰/重掷，计数=“可掷次数”，全面替换“投掷”“首掷”“剩掷”“空投”。
2. **两步锁定的称呼**：待选 / 待锁 / 确认锁定 / 清除待选。术语表未规定。建议保留两步交互（这是玩法设计），文字统一为：点骰子=“选中”，按钮=“锁定 N 颗”“取消选择”，骰子标签=“已选 1”。是否改为单击直接锁定是玩法决定，交由用户。
3. **结束本轮**：术语表 §1 已要求“应说清是结束本关”。候选：“结束本关 · 结算”（推荐）／“领奖励并结束本关”／“结算本关”。
4. **“挑战”双义**：整局（新建挑战、本次挑战结束）与关卡难度（普通挑战、高压挑战、开始挑战）。建议整局用“一局/对局”，“挑战”只留给普通/高压。
5. **奖励名**：结算“基础奖励”与关卡卡“过关奖励”指同一笔钱，且“基础奖励”与术语表的“基础分”易混。建议统一“过关奖励”；“剩余提交奖励”统一（废除“剩次奖励”“余次奖励”）。
6. **利息相关**：术语表把“现金、余额、净增”改为“金币”，但没有处理“利息”“计息本金”“计息本金上限”。建议保留“利息”，把“计息本金上限 25”改说成果“利息每关最多 +5”；C96、O10 的配置说明也用此说法（另一审查范围）。
7. **提交栏的数量词**：术语表要求“提交栏”，数值写“最多提交 5 颗”。但界面若干处需要名词形式（商店左栏“提交容量 5”、新骰“提交容量保持”）。建议补充“提交栏 N 格”。
8. **栏位 vs 槽 vs 免槽**：术语表要求“栏位”；界面大量“普通槽”“普通占槽”“空槽”“道具槽位”，附魔名“免槽”。附魔名改“不占栏位”需同步配置文本。
9. **“活动骰”**：术语表建议“本关可用的骰子”，太长，放不进“活动骰 5 · 永久骰 5”这类标签。建议标签用“骰子 N 颗（永久 N）”。
10. **骰子与骰面的称呼**：术语表要求不显示 D001、F01，但骰子没有名称。需要决定编号方式：建议“骰子 1…8”（按获得顺序）与“第 1 面…第 6 面”。改造、遥控、明细、回执都依赖此决定。
11. **“升级”vs“改造”vs“强化”**：术语表规定牌型/颜色用“升级”；骰面类商品现用“强化”（“支付 N 并强化”）与“改造”（分区名“骰面改造”）。建议骰面统一“改造”。
12. **稀有度名**：界面“常见/进阶/稀有”，GAME_OVERVIEW“普通/罕见/稀有”。需定一个。
13. **“连锁”**：实为“本手生效的控制器张数”。候选：“生效 N 张”（推荐）／“联动 N”。是否需要保留“连锁”这个演出词由用户定。
14. **横幅三档名**：高分（≥目标一半）/超高分（≥目标）/爆分（≥目标两倍）。候选：“过半！/一手达标！/两倍目标！”。属体验决定。
15. **超长数字格式**：“123456…（20位）”与“≈1.23e15”并存，需选一种（推荐“约 1.23×10¹⁹”）。
16. **左栏副标题**：删除“复古印刷骰桌”后此位置放什么（留空／“第 N 章”／种子），属界面决定。
17. **快捷键名称**：是否把 Enter、Backspace 本地化为“回车”“退格”。
18. **手册第三页名**：“成长与新机制”建议“进阶规则”。
19. **练习模式入口**：目前只在手册里（“独立固定骰练习”），且整套显示调试标签、关闭引导。是否在主菜单增加“练习”入口、是否在练习中显示引导，属范围决定。
